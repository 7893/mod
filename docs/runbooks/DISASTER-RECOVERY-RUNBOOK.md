# MOD 灾难恢复操作手册 (Disaster Recovery Runbook)

- 文档版本：v2.1.0
- 更新日期：2026-09-17
- 状态：现行
- 适用范围：生产主机故障、数据库损坏下的灾难恢复

---

## 灾备策略（2026-09-16 起）

**项目级 R2 备份链路已退役**（见 [KI-095](../issues/KI-095-项目级R2备份链路退役.md)）。

当前灾备依赖：

| 数据类型 | 备份方式 | 恢复方式 |
|----------|----------|----------|
| **数据库** | MySQL HeatWave 平台自动增量备份；2026-09-17 只读核验为启用、保留 1 天、PITR 关闭 | 仅能从 OCI 当时仍处于 `ACTIVE` 的可用备份创建新 DB System；不承诺任意时间点恢复 |
| **版本化代码与文档** | GitHub 仓库 | `git clone` |
| **运行配置与凭据** | 仓库外的受控环境机制 | 重新注入 `.env.systemd`；GitHub 不保存数据库运行凭据 |
| **本机受限历史原件** | 本机文件 + `MANIFEST.sha256` 完整性清单，无项目级异机备份 | 主机仍可访问时校验和复制；主机与底层存储同时丢失时可能无法恢复 |

## 恢复流程

### 场景：主机故障需重建

1. **新建主机**：Ubuntu 24.04+，安装 Python 3.13、Node.js、Nginx

2. **拉取代码**：
   ```bash
   git clone https://github.com/7893/mod.git /home/ubuntu/mod
   ```

3. **配置环境变量**：
   - 从安全渠道获取 `.env.systemd` 和 `.env.api.systemd`
   - 配置数据库连接、Cloudflare 凭据等

4. **恢复数据库**（如需）：
   - 登录 Oracle Cloud 控制台
   - 先确认自动备份仍为 `ACTIVE`；当前策略只保留 1 天且未启用 PITR
   - 从可用备份创建新的 MySQL DB System，再执行应用只读验收；若备份已过期，项目没有第二套数据库副本

5. **部署服务**：
   ```bash
   cd /home/ubuntu/mod
   bash scripts/project/publish.sh
   ```

## 历史备份存档

R2 中的历史加密对象不属于现行灾备能力，可能已经自然过期；不得把其存在、完整性或可恢复性作为操作前提。
仍需处置历史对象或密钥时，必须单独只读核实并取得云资源变更授权。
