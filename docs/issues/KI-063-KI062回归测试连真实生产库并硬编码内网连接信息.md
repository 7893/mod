## 结论

KI-062 随修复新增的回归测试 `backend/tests/test_ki062_propeller_wiring.py::test_ki062_live_propeller_step_advancement`
在默认测试路径中直接连接真实生产数据库并执行推进器写库路径，且源码内**硬编码了内网连接信息与默认账号**。
这同时触碰 `ENFORCEMENT.md` 的两条动作点闸门：

- **闸门 A（凭据不落地）**：源码保留可用的连接信息默认值——内网主机 `10.0.1.25`、默认用户 `admin`、默认库 `mod`，
  属"作为默认值的连接信息"，为闸门 A 明令禁止；同时依赖 `load_dotenv("/home/ubuntu/mod/.env.systemd")` 读取
  写权限运行环境。
- **闸门 B（数据库与生产操作）**：单元测试在默认 `make check` 路径下即连**生产 HeatWave 库**、走
  `ConstructionPropeller.step()` 写库路径并执行 `conn.commit()`，未经每次运行的显式授权与只读目标核验，
  违反"测试不触碰真实生产库、更不写库"的边界。

该测试当前之所以"通过"，恰恰是因为运行主机存在 `.env.systemd` 且能连通生产库；在 CI 或任何缺少该环境文件、
无法访问内网库的机器上，它会连接失败而使 `make check` 变红，破坏跨环境可复现性。KI-062 的接线保证已由同文件
两项 Mock 测试（enabled 调用推进器/回填器、disabled 严格 fail-closed）充分覆盖，本 live 测试不构成回归防护的必要项。

本条目属"已合入但违反安全边界的测试代码"缺陷（技术债），不是新功能需求。

## 只读证据（2026-09-09）

`backend/tests/test_ki062_propeller_wiring.py::test_ki062_live_propeller_step_advancement` 关键片段：

```python
load_dotenv("/home/ubuntu/mod/.env.systemd", override=True)
user = os.getenv("MOD_DB_USER", "admin")
password = os.getenv("MOD_DB_PASSWORD", "")
host = os.getenv("MOD_DB_HOST", "10.0.1.25")
port = int(os.getenv("MOD_DB_PORT", 3306))
db = os.getenv("MOD_DB_NAME", "mod")

conn = pymysql.connect(host=host, port=port, user=user, password=password, database=db, autocommit=False)  # secret-scan: allow
# ...
prop = ConstructionPropeller(conn=conn, seed=123)
res = prop.step(now=now_hkt, auto_commit=False)
# ...
conn.commit()
```

- 硬编码内网地址 `10.0.1.25`、默认账号 `admin`、默认库 `mod` 直接留在源码中。
- 无条件读取 `.env.systemd`（写权限运行环境），并在无 opt-in 守卫的情况下发起真实连接与 `commit()`。
- 该测试无 `pytest.mark.skipif` / 环境守卫，属默认收集执行项；`make check` 后端 225 项包含它。

## 根因

- KI-062 补齐主循环接线的回归测试时，为"贴近真实"直接写了一条连生产库的 live 测试，未按测试规范采用
  离线 Mock 或可选 opt-in 守卫，也未清除硬编码连接默认值。
- 缺少一道针对"测试是否连真实库/是否含硬编码连接信息"的约束，使该问题在 KI-062 自测"全绿"的表象下被带过。

## 影响

- 安全边界：源码含可用内网连接信息与默认账号（闸门 A）；默认测试路径对生产库执行写事务（闸门 B）。
- 可复现性：CI 或他机因无 `.env.systemd`、无法访问内网库而 `make check` 失败，测试结果与运行主机强耦合。
- 认知偏差：把"能连生产库"当作测试通过条件，掩盖了单元测试应离线自洽的要求。

## 修复方向（已完成）

1. 移除源码中的硬编码连接默认值（`10.0.1.25`、`admin`、`mod` 等），连接信息只从环境读取、无可用回退默认值。
2. 彻底移除连真实库的 live 测试，全面迁移为离线 Mock：接线保证由两项完全离线的 Mock 测试覆盖，不降低回归防护。
3. 全量复核测试套件与仿真模块（`test_quota_watchdog.py`、`test_governance_lifecycle.py`、`quota_watchdog.py`、`trickle_backfill.py`），清除所有硬编码 IP 与账号默认值，全面构建离线自洽测试基线。
