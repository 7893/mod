# KI-072 · 常驻模拟器生命周期编排、事务与安全状态未闭环

- 状态：OPEN
- 优先级：P0
- 更新日期：2026-09-09
- 适用范围：`mod-simulator` 常驻循环、六阶段生命周期、事务所有权、配额门禁、限流状态与运行健康发布门禁
- 关联：[已知问题看板](../KNOWN-ISSUES.md)、[业务拟真引擎](../development/BUSINESS-SIMULATION-ENGINE.md)、[模拟流水线规范](../development/SIMULATION-PIPELINE-SPEC.md)、[双轨运行定义](../development/DUAL-RUN-DEFINITION.md)、[KI-040 模拟器安全边界](KI-040-模拟器运行安全边界未闭环.md)、[KI-062 治理推进器接线](KI-062-治理自愈推进器已就位但未接入模拟主循环而静默失效.md)

## 结论

KI-062 已把 `ConstructionPropeller` 与 `TrickleBackfiller` 接入慢周期，但正式的六阶段
`LifecycleAdvancer/EvolutionCoordinator` 仍未进入常驻服务主循环。与此同时，子模块会提交调用方拥有的事务，
长期门槛只保存在内存，AI 配额采用“先调用、后记账”，状态接口又把限流和 dry-run 报告为运行中。
这意味着模拟器既不能按设计自然推进完整生命周期，也不能兑现单事务回滚、长期规则和硬配额承诺。

## 只读证据（2026-09-09）

1. `LifecycleAdvancer` 的运行时调用只存在于测试、独立脚本和 `evolution_coordinator.py`；
   `runtime_service.py` 的慢周期仅生成储备池准入、双轨核对或培训事件，没有完整六阶段编排。
2. `runtime_service.py` 声明单连接单事务并在周期末提交，但 `TrickleBackfiller.run_cycle` 和
   `QuotaWatchdog.record_consumption` 会对传入连接自行 `commit`，后续异常无法整体回滚。
3. 建设成功审计在周期最终提交之前写出；若后续推进器、回填或检查失败，可能同时留下成功审计和失败结果。
4. 生命周期连续达标天数、第八批每周准入次数与最小间隔存于进程内，服务重启或发布后重置。
5. AI 配额的 `can_consume` 与实际外部调用、`record_consumption` 分离；并发调用可同时通过，实际消耗在调用后才记录。
   配额日期使用 UTC，而展示与模拟业务日使用 HKT。
6. `_save_status` 将除 `ERROR` 外的 `RATE_LIMITED`、`DRY_RUN` 等周期状态统一映射为服务 `RUNNING`；
   发布检查主要验证 JSON 字段存在，不能证明服务新鲜、未熔断或最近周期成功。
7. 日/分钟限流状态缺少跨进程原子保护；持久化日期领先本机时钟时，当前逻辑可能把计数视为零并重写日期。

## 影响

- 单位不会按正式门槛稳定地完成全生命周期，治理推进器可能成为绕过生命周期评审的主要跃迁路径。
- 周期失败后数据库可能已有部分提交，而返回结果和审计声称回滚或失败，破坏可追溯性。
- 重启会改变准入节奏和连续达标结果，长期演示不具确定的业务含义。
- “每日 3000 Neurons、账单恒为零”不是严格硬门禁；健康接口和发布门禁可能掩盖停止写入或限流状态。

## 修复边界与方向

1. 明确唯一编排器，将六阶段 `EvolutionCoordinator/LifecycleAdvancer` 接入常驻慢周期；治理推进器只能在
   正式门槛允许的范围内补充治理，不得直接绕过生命周期评审。
2. 由 `SimulatorRuntimeService` 独占事务提交权；所有 writer、propeller、backfiller、quota 子模块支持
   `auto_commit=False` 且不得提交外部连接。审计应在数据库提交成功后记录，或纳入同一可恢复事务。
3. 把连续天数、阶段进入时间、每周准入记录和限流状态持久化，并建立进程单例/数据库锁，保证重启和并发一致。
4. 把配额改为调用前原子预留、调用后按实际值结算/退还；业务日统一使用配置时区；额度状态不可用时 fail-closed。
5. 重新定义运行状态：`RUNNING/DEGRADED/RATE_LIMITED/DRY_RUN/HALTED/STALE` 不得互相冒充；发布门禁必须校验
   heartbeat 新鲜度、最近周期、熔断状态、运行模式和所需写入能力。

## 完成定义

- [ ] 常驻服务通过唯一编排器覆盖全部六阶段，状态跃迁逐项满足规范门槛并留评审足迹。
- [ ] 任一步骤失败时本周期所有数据库写入均回滚，且不会留下成功审计或已消费但未记账的内部状态。
- [ ] 重启前后连续达标、阶段进入日、准入频率、日/分钟限额保持一致；双实例不能突破围栏。
- [ ] AI 配额在并发和实际用量超估/低估场景下仍不突破免费边界，HKT 日切一致。
- [ ] 状态 API 和发布检查能拒绝 stale、dry-run 冒充 enabled、已熔断及最近周期失败的服务。
- [ ] 增加编排接线、事务回滚、重启恢复、并发额度、时钟回拨和发布门禁回归测试。
- [ ] 同步模拟器现行规范与 `CURRENT-STATE.md`；`make check` 全绿。
