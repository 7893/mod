# KI-037 · 省级二级单位实体化（组织层级从两层到三层）

- 状态：DRAFT（立项存档，暂不实现，待排期）
- 优先级：P3
- 更新日期：2026-09-07
- 关联：[KI-035 模拟器单位动态增长](KI-035-模拟器单位动态增长.md)、[拟真引擎业务规范](../development/SIMULATION-PIPELINE-SPEC.md)、[数据与安全标准](../development/DATA-AND-SECURITY-STANDARD.md)

## 背景

当前组织维度是**逻辑两层**：单位带有"省份归属"标签（`province_config.py` 定义 31 省的等级/
目标数/业务系数），可按省筛选与汇总。但省份只是**配置与分类参数**，不是数据库里的实体机构。

即：**我们有"省份归属"这个维度标签，但没有"省级二级单位"这个组织实体。** 现有约 2001 家
基层单位直接挂在省份标签下，缺少真实世界"总部 → 省级分公司 → 基层单位"的中间实体层。

若要在大屏做"点开一个省级公司、看它管辖的下属单位"这类组织树下钻，才需要把二级单位实体化。
若仅需"按省汇总看数"，现有归属标签已足够，无需本 KI。

## 关键认知（本 KI 的成本核心）

省级二级单位一旦实体化，**不是凭空多 34 行记录，而是多 34 家要走全套生命周期的真实单位**。
这与 KI-035（单位动态增长）是同量级甚至更大的连锁，因为它改动的是**组织层级结构本身**。

连锁影响：

1. **新的单位层级/类型**：组织模型要引入"二级单位"层级；基层单位挂 `parent_id` 到所属二级单位，
   形成三层组织树（总部 → 省级二级单位 → 基层单位）。
2. **推广/上线时序**：二级单位自身也有上线批次与建设进度；逻辑上二级单位应**先于**其下属基层
   单位上线（先建省公司，再铺基层），新增一层时序约束。
3. **人员**：每个二级单位要有自己的领导班子/经办人（`org_user`），不能是空壳机构。
4. **建设进度 / 数据准备度**：每个二级单位一套 `construction_task`、`data_readiness`。
5. **业务归集口径**：二级单位是纯汇总节点，还是自身也产生本级业务单据？需明确（真实世界省公司
   通常也有本级业务）。
6. **勾稽全面重算**：单位总数口径变化（2001 是否 +34？分母如何界定），所有以单位总数为分母的
   百分比（上线率、建设率等）全部重算——与 KI-035 同一类雷区。
7. **模拟引擎支持**：生命周期推进器、名字生成器（省级公司命名规则不同于基层单位）、入池逻辑
   都要认识"二级单位"这一新类型。

## 目标

在组织模型中实体化"省级二级单位"层级，使组织从逻辑两层升级为实体三层，支撑大屏的组织树下钻，
同时保持全站勾稽自洽、模拟数据不产生脏数据、严守既有模拟器约束。

## 待拍板事项（决定是否启动本 KI）
1. **是否需要**：大屏是否真需要"点开省级公司看下属单位"的组织树下钻？若只需按省汇总，本 KI 可长期搁置。
2. **二级单位数量与命名**：34 个（按省）还是其他口径？省级公司命名规则。
3. **业务口径**：二级单位是纯汇总节点还是自身也产生本级业务。
4. **单位总数口径**：实体化后总纳管口径如何界定，勾稽如何统一。
5. **上线时序规则**：二级单位与其下属基层单位的先后约束。

## 完成定义（实现时）
- 组织三层结构落地，基层单位正确挂靠省级二级单位。
- 二级单位有完整人员/建设进度/准备度，遵守上线时序（先于下属单位）。
- 全站勾稽一致，单位总数口径统一，百分比分母正确。
- 模拟引擎认识二级单位类型，名字符合命名规则且查重，无脏数据。
- 回归测试覆盖：三层归属正确性、时序约束、勾稽一致性、命名查重。
- `make check` 全绿；文档同步。
