# KI-044 · 仓库部署配置与生产实际严重漂移

- 状态：OPEN
- 优先级：P1
- 更新日期：2026-09-07
- 关联：[已知问题看板](../KNOWN-ISSUES.md)、[ADR-0008 前后端统一软链发布隔离](../decisions/0008-前后端统一软链发布隔离.md)

## 结论

仓库中维护的部署模板（systemd 配置文件、Nginx 站点配置）与生产实际运行状态发生显著漂移：
1. 仓库 `deploy/mod-api.service` 仍指向 `backend/`，生产主机实际使用的是 `backend/current`（基于软链发布）。
2. 仓库 Nginx 模板 `deploy/nginx/mod.conf` 仍指向 `frontend/dist`，没有指向软链发布目录 `frontend/current`。
3. 仓库 Nginx 配置中 SSE 反向代理路径写成 `/api/v2/live-projection/events`，而实际业务代码为 `/api/live-projection/events`。
4. 生产环境现存的 CloudFront 回源鉴权、证书路径与自定义限流策略未固化到仓库配置资产中。
5. 一旦发生机器灾难重建或依据仓库模板重新初始化，将导致服务无法启动、前端版本回退、SSE 通信中断或暴露源站。

## 修复目标

- 消除所有配置漂移：将线上验证可用的 systemd unit、Nginx 反向代理配置、路径与证书配置双向同步回仓库 `deploy/`。
- 固化 CloudFront 与源站通信保护规则，确保具备可复现的 IaC / 配置基线。
