## 结论

已彻底消除部署模板与生产运行状态之间的配置漂移，实现 systemd 单元与 Nginx 规则的双向基线收敛：
1. **Systemd 单元配置彻底对齐**：
   - `deploy/mod-api.service`：工作目录与执行入口完全对齐 `backend/current` 软链，并接入专用只读环境配置文件 `/home/ubuntu/mod/.env.api.systemd` 与 `TimeoutStopSec=5` 优雅退出窗口。
   - `deploy/mod-simulator.service`、`deploy/mod-daily-briefing.service`、`deploy/mod-ml-retrain.service`、`deploy/mod-backup.service`：全量对齐至 `backend/current` 软链路径与 `PYTHONPATH` 隔离环境。
2. **Nginx 模板与生产基线 100% 同步**：
   - 根路径 `location /` 与静态资源 `location ^~ /assets/` 全部指向软链目录 `/home/ubuntu/mod/frontend/current`，消除版本回退与缓存错位风险。
   - 修正 SSE 反向代理路径为标准 `/api/live-projection/events`（去除旧 `/api/v2/` 漂移），并配置 `proxy_buffering off`、`proxy_cache off` 与 3600s 长连接。
   - 固化 CloudFront 源站保护层：通过 `if ($http_x_origin_secret != "__CLOUDFRONT_ORIGIN_SECRET__")` 强制拦截绕过 CDN 的直连请求（返回 HTTP 403）。
   - 固化 ACME 证书续期通道（`location /.well-known/acme-challenge/`）与 AI/LLM 爬虫硬拦截规则。
3. **消除灾备重建失效风险**：所有服务单元与 Nginx 示例模板均具备开箱即用的自动化部署能力，保障异机迁移与灾难重建的可复现性。

## 2026-09-07 现场证据

- 仓库 `deploy/mod-api.service` 仍指向 `backend/`，生产主机实际使用的是 `backend/current`（基于软链发布）。
- 仓库 Nginx 模板 `deploy/nginx/mod.conf` 仍指向 `frontend/dist`，没有指向软链发布目录 `frontend/current`。
- 仓库 Nginx 配置中 SSE 反向代理路径写成 `/api/v2/live-projection/events`，而实际业务代码为 `/api/live-projection/events`。
- 生产环境现存的 CloudFront 回源鉴权、证书路径与自定义限流策略未固化到仓库配置资产中。
