## 结论

经过 KI-029（六屏叙事重构）与 KI-033（前端 UI 优化美化），MOD 驾驶舱确立了 6 大屏幕、36 个稳定 Zone 编号（`A1`～`F5`）的物理防爆舱布局体系。但在近期的端到端业务闭环审计与数据可视化信息熵复盘中发现，**部分面板存在严重的“同质化数据套娃”、“低信息熵静态死卡”以及“图表名不副实”等业务与技术负债**。

突出表现为：
1. **`D3`（链路规模对比）与 `D1`、`D2` 严重数据重叠**：在同一个 D 屏内，以三种不同形状（柱状图、流程链、柱状图）展示完全相同的单据、凭证、接口和双轨总量，信息增量几乎为零；
2. **`A8`（项目联系人覆盖）信息熵过低且位置错配**：联系人覆盖率常态化 100%，缺口恒为 0，且与 `A1` 顶栏重复、与 `C5` 功能完全重合，在寸土寸金的 A 屏（总指挥大盘）沦为毫无预警价值的“静态死卡”；
3. **`C3`（上线趋势）名不副实**：标题标为“上线趋势”，但底层 X 轴并非时间序列（Time Series），而是 8 个静态批次名称，本质上是将上方 `C2` 面板的数据换算为百分比后重新画了一遍；
4. **`D7`（数据质量金标准核验）下半部全 100% 静态图占据过大面积**：4 根静态 100% 的柱状图独占大半张屏，有效数据墨水比（Data-to-Ink Ratio）极低；
5. **`B4`（培训赋能全景）业务权重失衡**：在工程建设屏中独占 8 列大面积展示 3 张培训行政类图表，挤压了更硬核的期初对账阻塞与关键接口联调等高危风险的呈现空间。

## 影响分析

1. **稀释指挥大屏的核心决策效率**：大屏黄金地段被不变化或重复的数据占领，管理层无法在第一眼捕获真正的经营异动和业务堵点。
2. **削弱系统的专业度与权威感**：财务专家、项目总监与审计人员在评审时，容易识别出“为了填满网格而拼凑同质图表”的痕迹，降低对底层数据严肃性的信任。
3. **时间维度利用不足**：现有 `daily_stats` 与 `rollout_status_snapshot` 已保存可用于趋势分析的真实数据，
   页面却仍以累计总数和静态批次为主，未把已有时间序列转化为决策信息。

## 治理与重构方案

在保持现行 **36 个稳定 Zone 编号不变**、**前端 Grid 物理防爆舱结构不破坏**的前提下，对上述面板进行渐进式业务重构：

### 1. `D3`：静态总量阶梯 ➔ 「近 7 日业务吞吐」

- **业务定位**：`D1` 负责累计规模，`D2` 负责链路节点，`D3` 只回答“最近每天处理了多少、集成质量如何变化”。
- **真实数据源**：`daily_stats.stat_date/doc_today/voucher_today/integration_count/integration_success`。
- **展示内容**：单据日增量、凭证日增量双柱与当日集成成功率折线；Tooltip 展示精确值。
- **明确删除**：没有数据源的 TPS、当前并发、毫秒延迟和“HeatWave 极致吞吐”宣传性指标。业务到达量不等于数据库引擎吞吐，禁止混为一谈。

### 2. `A8`：联系人覆盖 ➔ 「运营红线哨位」

- **业务定位**：联系人信息只保留在 C5；A8 汇总总览屏尚未集中呈现的运营异常。
- **真实数据源**：`operations.integrationFailed`、`operations.dualRunInconsistent`、`quality` 三项异常合计。
- **展示内容**：接口失败、双轨差异、金标异常三类横向比较，以及异常总数/全通过状态。
- **安全边界**：只显示聚合数量，不显示单位、人员、单笔金额和凭证内容；没有正式规则前不引入“5,000 万元阈值”“越级审批”等硬编码告警。

### 3. `C3`：伪趋势组合图 ➔ 「批次上线爬坡矩阵」

- **业务定位**：C2 看当前批次构成，C3 看各批次随时间的上线率变化，两者不再重复。
- **真实数据源**：`rollout_status_snapshot.snapshot_date/status` 与当前受控批次映射。
- **展示内容**：日期 × 批次热力矩阵，颜色表达上线率，Tooltip 同时显示上线率、双轨率和样本单位数；避免 8 条折线互相挤压。
- **明确删除**：在没有计划基线表之前不展示 Baseline vs Actual，也不虚构历史里程碑。

### 4. `D7`：全 100% 柱图 ➔ 「金标核验覆盖规模」

- **业务定位**：保留四项紧凑状态带，主图改为比较每项规则实际核验的数据规模与检出异常。
- **真实数据源**：现有 `quality` 与 `operations` 派生的 `qualityAuditList`。
- **展示内容**：使用明确标注的对数尺度比较不同数量级的核验规模，标签显示精确数量，Tooltip 显示异常数与合规率。
- **事实纠偏**：MOD 当前没有数据库触发器；不得展示“触发器已启用”。页面只描述实际存在的应用层事务校验与只读金标核验。

### 5. `B4`：培训三图 ➔ 「上线门禁攻坚」

- **业务定位**：突出决定能否上线的关键建设门禁，培训只保留一张总体转化漏斗。
- **真实数据源**：`construction.taskStages` 中期初数据、接口联调、双轨验证、用户培训四阶段，以及 `trainingSummary`。
- **展示内容**：关键门禁完成率/待推进任务比较 + 总体参培认证漏斗。
- **明确删除**：没有来源的银企/ERP 阻塞清单和“期初财务对账平衡率”；如后续确有明细 API，再另行接入。

## 约束与验收标准

1. **契约不破**：全局 36 个 Zone 编号（`A1`～`F5`）保持稳定，不增删面板标识，不改变各屏的基础网格栅格（Grid Layout）。
2. **严守代码规范**：所有重构严格遵守 `CockpitPanel` 统一组件体系，零私有手写 `<style>`，Tailwind 任意值 lint 0 命中，单个 View 文件严格保持在 400 行以内约束。
3. **数据源真实可追溯**：新引入的吞吐量与告警流数据，必须由现有拟真引擎或只读 API 真实计算派生，严禁前端硬编码伪造无源数据。
4. **信息不套娃**：D3 不再出现累计总量阶梯；A8 不再出现联系人覆盖；C3 不再按静态批次重复 C2 的当前构成。
5. **缺失态诚实**：新增字段缺失时显示 `—` 或明确空态，不得以冻结快照、百分之百或零异常兜底。
6. **可视化可读**：同一图表不堆叠 6 条以上折线；Tooltip 承载明细，主画布只保留核心比较关系。
7. **回归覆盖**：测试覆盖日累计转日增量、批次热力矩阵、缺失态、零异常、异常聚合、图表标签与原有 Zone 编号不变。
8. **人工视觉验收**：自动检查通过后，由人工在 1920×1080、1440 宽度、浏览器全屏和窗口缩放场景确认无溢出、遮挡或异常留白。
9. **文档同步**：实现完成后更新 `docs/CURRENT-STATE.md`、前端规范、本 KI 状态和进度；不得只改页面不回写事实。

## 实施顺序

1. 后端新增两个只读派生序列并补契约测试，不改变现有字段。
2. 先完成 C3、D3 两个重复度最高的趋势面板。
3. 再完成 A8、D7、B4 的内容替换，不改变各屏现行 Grid。
4. 完成自动化检查后交由人工做真实页面视觉验收；不把未执行的视觉验收写成完成。
