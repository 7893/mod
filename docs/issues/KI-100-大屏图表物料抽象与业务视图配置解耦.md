# KI-100 · 大屏图表物料抽象与业务视图配置解耦

编写日期：2026-09-17
- 状态：OPEN
- 优先级：P2
适用范围：前端六屏组件（A1~F5）、通用图表物料库、Composables 抽象层

## 问题与证据

- **关注点严重混杂**：Vue 视图层（如 `CockpitTopBar.vue`、`ConstructionView.vue`、`InsightsView.vue`、`IssuesView.vue`、`RolloutView.vue` 等）内部承载了大量长达数十行至上百行的 ECharts Option 拼装计算属性，视图组件直接依赖底层 Canvas 渲染参数。
- **公共与定制割裂**：虽然建立了 `src/charts/` 目录，但仅收拢了部分大屏面板图表；多个特定业务卡片与下钻视图仍采取内联手写方式，导致代码重复率高且修改困难。
- **状态处理与生命周期简陋**：各图表对于空数据态（Empty State）、加载骨架（Loading Skeleton）以及渲染异常缺少开箱即用的统一容器包裹，遇到无数据时只能依赖外层粗糙的 `v-if` 或绘制空轴。

## 目标与方案

1. **构建图表高阶物料层**：
   在 `frontend/src/components/charts/` 或通过 Composable 工厂模式，封装通用业务图表组件（如 `BarChartCard`、`RingGaugeCard`、`TrendLineCard`），内建统一的加载态、空态占位及防抖 resize。
2. **彻底解耦视图与配置**：
   业务 Vue 组件一律只负责接收数据 Props 并传递给图表组件，严禁在 `.vue` 文件中直接声明 ECharts option 字典对象。
3. **收敛全部工厂函数到 `charts/`**：
   将目前散落在 Vue SFC 内的图表配置全部抽离为纯函数（Pure Functions），并配套 Vitest 单元测试保障纯函数的输出契约。

## 修复范围与验收

- [ ] 抽离并封装高阶图表物料组件，内建统一骨架屏与 EmptyNote 插槽。
- [ ] 重构 A1 顶栏（`CockpitTopBar.vue`）及六屏各视图，移除全部内联 ECharts Option 计算属性，收拢至 `charts/` 工厂。
- [ ] 业务 Vue 文件平均行数减少 25% 以上，彻底杜绝 ECharts 渲染细节污染业务视图。
- [ ] 确保全屏等比缩放及下钻交互行为完全不受影响，通过视觉回归测试。
- [ ] `pnpm test` 与 `make check` 门禁全绿通过。

## 边界

- 保持对外展示的视觉样式与交互逻辑完全一致，仅做内部架构与分层重构。
- 不影响现有 Pinia Store 与 API 请求契约。
