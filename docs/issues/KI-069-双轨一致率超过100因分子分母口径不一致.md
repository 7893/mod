# KI-069 · 双轨核对一致率超过 100%（分子分母口径不同源）

- 状态：OPEN
- 优先级：P2

- 适用范围：驾驶舱 D6「双轨运行核对」面板一致率指标、快照 `operations.dualRunConsistencyPct` 的计算口径
- 关联：[已知问题看板](../KNOWN-ISSUES.md)、[KI-053 双轨运行真实性演进](KI-053-双轨运行真实性演进.md)、[双轨运行与脱离双轨定义](../development/DUAL-RUN-DEFINITION.md)、`backend/app/services/dashboard.py`

## 结论

线上 `operations.dualRunConsistencyPct` 出现 **102.65%** 的不可能值（一致率不应 > 100%）。根因是该比值的
**分子与分母来自不同表、不同时点**：分子取自 `dual_run_result` 实时全表聚合，分母取自 `daily_stats` 的滞后
快照列 `dual_run_count`。模拟器持续向 `dual_run_result` 写入使实时"一致"数超过滞后快照的"总数"，比值即破 100%。
属既有数据正确性缺陷，与 KI-053 无关（KI-053 新增的 `dualRunBreakdown` 维度一致率口径正确，为约 92.x%）。

## 只读证据（2026-09-09）

- 线上 `GET /api/dashboard/snapshot` → `operations.dualRunConsistencyPct = 102.65`。
- 同一响应 `operations.dualRunBreakdown` 三维度真实数据（口径正确）：
  - 业务单据金额核对 92.7%（一致 9937 / 不一致 781 / 共 10718）
  - 凭证借贷汇总核对 93.2%（一致 9980 / 不一致 731 / 共 10711）
  - 月末科目余额比对 92.5%（一致 9910 / 不一致 798 / 共 10708）
  - 合计：一致 29827 / 总 32137 ≈ **92.8%**（真实一致率）。
- `backend/app/services/dashboard.py::build_dashboard_snapshot_v2` 中：
  - 分子 `dual_consistent` 来自 `SELECT check_type, result, COUNT(*) FROM dual_run_result GROUP BY ...` 的实时"一致"累加；
  - 分母 `ops["dual_run_count"]` 来自 `daily_stats`（`SELECT ... FROM daily_stats WHERE stat_date = (SELECT MAX(stat_date) ...)`）的滞后快照值；
  - `dualRunConsistencyPct = round(dual_consistent * 100 / ops["dual_run_count"], 2)` —— 分子分母不同源，实时增长后分子 > 分母 → 结果 > 100%。

## 影响

- D6「双轨运行核对」面板顶部一致率可显示 > 100%（如 102.65%），大屏上明显穿帮，削弱可信度。
- 与同面板 `dualRunBreakdown`（约 92.8%）自相矛盾，观众可直接看出不一致。

## 修复方向（待实施；需按 ENFORCEMENT 确认范围与授权）

- 让 `dualRunConsistencyPct` 的分母与分子**同源**：改用 `dual_run_result` 实时全表总数
  （即 `dual_consistent + dual_inconsistent`，或对该表直接 `COUNT(*)`），而非 `daily_stats.dual_run_count` 滞后快照。
- 复核 `operations.dualRunConsistent` / `dualRunInconsistent` 与 `dualRunBreakdown` 是否同源，确保 D6 顶部一致率
  与三维度穿透口径一致（都约 92.8%）。
- 保持 KI-059 秒级 SLA：`dual_run_result` 已有分组聚合查询，复用其结果计算分母，不新增额外全表扫描。
