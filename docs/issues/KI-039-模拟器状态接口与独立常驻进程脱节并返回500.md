# KI-039 · 模拟器状态接口与独立常驻进程脱节并返回 500

- 状态：DONE
- 优先级：P1
- 更新日期：2026-09-07
- 关联：[已知问题看板](../KNOWN-ISSUES.md)、[KI-038 模拟器备份放大](KI-038-常驻模拟器重复全量备份导致磁盘耗尽风险.md)、[ADR-0008 前后端统一软链发布隔离](../decisions/0008-前后端统一软链发布隔离.md)、[ADR-0009 拟真引擎平移](../decisions/0009-拟真引擎平移为顶层独立模块.md)

## 结论

生产接口 `GET /api/simulator/status` 当前返回 HTTP 500。直接原因是接口导入旧的 API 进程内模拟器模块，
该模块又在导入阶段依赖顶层 `simulation` 包；API 从 `backend/` 或独立后端 release 启动时，仓库根目录不在其模块搜索路径中，最终触发 `ModuleNotFoundError`。

但本问题不能只靠添加 `PYTHONPATH` 或把 `simulation/` 复制进后端 release 解决。ADR-0009 已明确拟真引擎是独立顶层模块和独立常驻进程，
当前接口却仍返回 `backend/app/business_simulator.py` 中旧进程内单例的状态。即使修好导入，它也不能代表真实的 `mod-simulator.service`。
正确修复应让只读接口读取独立模拟器发布的结构化心跳，并彻底解除状态查询对旧模拟器模块的导入依赖。

## 2026-09-07 现场证据

- 生产请求 `GET https://mod.fuming.name/api/simulator/status` 返回 **HTTP 500**，响应正文为 `Internal Server Error`。
- `mod-api` 日志显示异常发生在 `backend/app/business_simulator.py` 导入阶段：`ModuleNotFoundError: No module named 'simulation'`。
- `backend/app/business_simulator.py` 顶层执行 `from simulation.models import ...`。
- 后端发布脚本 `scripts/project/publish.sh` 只复制 `backend/app/` 到 `backend/releases/<timestamp>/`，不会把仓库顶层 `simulation/` 打入 API release。
- 现有接口调用 `get_simulator_instance()`，读取的是 API 进程内旧单例；真实模拟器则由独立的 `mod-simulator.service` 运行。
- 真实常驻进程持续写入 `output/simulator_status.json`。立项时该心跳文件存在且为新鲜状态，服务状态为 `RUNNING`，证明“模拟器在运行”与“API 返回 500”同时发生。
- 现有接口测试从仓库开发环境导入模块，仓库根目录恰好可见，因此没有复现生产 API 启动目录和 release 内容边界。

## 已确认根因

1. **状态来源错误**：接口仍查询旧的 API 进程内 `BusinessSimulator` 单例，而非独立常驻模拟器的真实心跳。
2. **模块边界错误**：API 状态查询导入 `business_simulator.py`，导入时强依赖已平移到仓库顶层的 `simulation` 包。
3. **发布边界不匹配**：后端 release 按设计只包含 API 的 `app/` 内容，顶层模拟器包不属于 API 制品。
4. **测试环境失真**：测试在仓库根目录或包含仓库根目录的 `sys.path` 下运行，没有覆盖“只提供后端 release”的生产等价场景。
5. **发布探针不完整**：统一发布只验证 `/api/health`，未验证 `/api/simulator/status`，所以该路由回归没有触发自动回滚。

## 修复目标

- `GET /api/simulator/status` 成为独立常驻模拟器的真实、只读、稳定状态接口。
- 查询接口不导入、不创建、不启动模拟器，也不连接写库。
- API 在只包含后端 release 的启动环境中可独立运行，不依赖仓库根目录被偶然加入 `PYTHONPATH`。
- 心跳新鲜、过期、缺失、写入中、格式损坏或无权限等状态都有确定响应，不出现未捕获的 HTTP 500。
- 发布流程能在切换后立即发现该接口回归并自动回滚。

## 接口契约要求

### 1. 唯一状态来源

- 以独立模拟器生成的 `output/simulator_status.json` 为运行状态来源，不再读取 API 进程内旧单例。
- 状态文件路径必须由集中配置解析；生产默认路径需与 `scripts/agy/run_simulator_service.py` 一致，不得在多个模块各自拼接不同路径。
- 接口不得调用 `systemctl`、启动子进程、导入模拟器业务模型或触发任何数据库读写。
- 状态响应必须使用字段白名单，不得把整个状态文件或任意异常文本原样透传给客户端。

### 2. 稳定响应语义

- 新鲜且有效的心跳：HTTP 200，返回 `service`、`status`、`last_cycle_status`、`timestamp`、`fresh`、`fail_closed_tripped` 和受控的熔断计数。
- 心跳过期：HTTP 200，显式返回 `status=STALE`、`fresh=false` 及最后心跳时间；过期阈值应集中配置并覆盖测试。
- 文件尚不存在：HTTP 200，返回 `status=UNAVAILABLE`、`fresh=false` 和不泄密的说明，视为可预期的未启动/未产生日志状态。
- JSON 正在切换或内容暂时不可读：不得抛出未捕获异常；应有限重试后返回结构化 `UNAVAILABLE`。
- 权限、持续 I/O 或不可恢复的内部错误：允许返回结构化 HTTP 503，但禁止返回无信息的 500，也禁止泄露绝对路径、堆栈、凭据或原始异常详情。
- 字段类型、时区和枚举必须固定，前端或调用方无需猜测 `null`、字符串与数字之间的变化。

### 3. 心跳写入一致性

- `simulation/runtime_service.py` 写心跳时应先写同目录临时文件，刷新完成后使用原子替换，避免 API 读到半段 JSON。
- 临时文件和正式文件权限必须遵循最小权限原则，并保证 `mod-api` 只有读取所需权限。
- 写入失败只能影响状态可见性，不得绕过模拟器既有 fail-closed、安全门禁或审计机制。

### 4. 清理错误依赖

- `backend/app/api.py` 的状态路由不得再导入 `backend/app/business_simulator.py`。
- 不得把“扩大 API 的 `PYTHONPATH`”或“把完整 `simulation/` 打进 API release”作为本 KI 的最终方案；这会重新耦合两个独立运行单元。
- 对旧进程内模拟器模块的整体移除可另行处理；本 KI 至少要保证 API 启动和状态查询不再依赖它。

### 5. 补齐发布探针

- `scripts/project/publish.sh` 在切换软链并重启 API 后，除 `/api/health` 外还必须验证 `/api/simulator/status`。
- 探针不仅检查 HTTP 状态码，还要验证响应为 JSON、包含稳定契约字段，且没有 `Internal Server Error`。
- 探针失败时沿用现有原子发布回滚流程，不得留下前后端指向不同批次的半发布状态。

## 禁止做法

- 不得通过捕获所有异常后伪造 `enabled=false` 来掩盖真实运行状态。
- 不得让 GET 状态请求创建模拟器实例、建立写库连接或改变服务状态。
- 不得从 API 执行 `systemctl`、shell 命令或读取 journal 日志。
- 不得硬编码主机绝对路径、环境凭据或线上域名到业务代码。
- 不得为了让测试通过而永久修改全局 `sys.path`。
- 不得把 KI-038 的备份清理或磁盘修复混入本任务；两项可以同批发布，但必须分别验收。

## 验收标准

### 自动化验证

- 新鲜心跳：接口返回 HTTP 200、`fresh=true`，字段和值与样例心跳一致。
- 过期心跳：接口返回 HTTP 200、`status=STALE`、`fresh=false`。
- 文件缺失：接口返回 HTTP 200、结构化 `UNAVAILABLE`，不产生写操作。
- 空文件、截断 JSON、错误字段类型和非法时间戳：均返回确定的结构化状态，不出现 500。
- 权限或持续 I/O 错误：返回结构化 503，响应不包含绝对路径、堆栈和凭据。
- 并发读写测试证明原子替换生效，接口不会读取半文件。
- 断言状态路由不导入 `business_simulator`、不创建数据库引擎、不执行子进程。
- 新增生产等价测试：只暴露后端 release 内容、从 API 的实际工作目录启动，仓库根目录不在 `PYTHONPATH`，状态接口仍通过。
- 发布脚本探针测试覆盖成功与失败回滚分支。
- `make check` 全绿，现有 API 与模拟器测试不得退化。

### 运行态验证

- 经授权发布后，连续请求生产 `/api/simulator/status` 至少 10 次，全部为结构化响应且无 HTTP 500。
- 在 `mod-simulator.service` 正常运行时，接口显示新鲜心跳，关键字段与 `output/simulator_status.json` 对应。
- 受控暂停模拟器并越过新鲜度阈值后，接口显示 `STALE`；恢复服务后自动回到真实运行状态。
- 临时使用测试状态路径复现文件缺失和损坏，确认响应符合契约；不得破坏或覆盖真实生产心跳。
- `mod-api` 日志中不再出现该路由触发的 `ModuleNotFoundError` 或未处理堆栈。
- 从后端当前 release 检查，确认修复不依赖仓库根目录 `simulation/` 被加入 API 模块搜索路径。

## 非目标

- 本 KI 不解决 KI-038 的重复全量备份和磁盘占用问题。
- 本 KI 不改变模拟器的数据生成规则、事件频率、每日上限或数据库 schema。
- 本 KI 不新增远程启停模拟器、清除 fail-closed 标记等写接口。
- 本 KI 不要求在本次任务中彻底删除全部旧模拟器代码，但不得继续由状态路由依赖它。
