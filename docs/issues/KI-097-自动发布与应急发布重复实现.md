## 问题

[`.github/workflows/quality.yml`](../../.github/workflows/quality.yml) 的 deploy job 与 [`scripts/project/publish.sh`](../../scripts/project/publish.sh) 分别实现 SSH、rsync、release 目录、软链切换、依赖同步、服务重载、健康探针和回滚相关逻辑。两个入口需要保留，但完整实现重复会持续产生行为漂移；当前脚本的本地与远程分支也分别引用独立服务和统一 `mod.service`，增加理解成本。

## 完成定义

- [ ] 发布动作只有一个可重复执行的权威实现；
- [ ] GitHub Actions 与本地应急入口只负责参数、凭据来源和调用；
- [ ] 依赖同步、软链切换、服务重载、健康探针、失败回滚和旧版本保留行为一致；
- [ ] 自动入口保持严格主机密钥校验和最小权限；
- [ ] 隔离环境完成成功、探针失败和回滚演练。
