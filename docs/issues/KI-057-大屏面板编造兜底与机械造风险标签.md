# KI-057 · 大屏面板编造兜底数据与机械 id 规则造风险标签

- 状态：DONE
- 优先级：P2
- 更新日期：2026-09-08
- 适用范围：六屏驾驶舱面板 A1~F5 的业务逻辑与数据真实性全面复查后发现的假数据问题
- 关联：[KI-023 AutoML 质量分硬编码兜底](KI-023-AutoML质量分硬编码兜底.md)、[KI-048 驾驶舱低效面板治理](KI-048-驾驶舱低效面板治理与高价值业务重构.md)、[KI-056 批次映射硬编码](KI-056-批次映射硬编码导致新单位错归第八批.md)

## 背景

对六屏全部面板（A1~F5）逐一复查业务逻辑与 bug。整体结论：绝大多数面板逻辑健壮、
防御与诚实标注到位（尤以 A、D 屏为佳），无崩溃类 bug。但发现若干面板存在"编造兜底数据"
与"用单位 id 机械规则派生风险标签"的真实性问题，与项目"要真实、不造假"的原则相悖。

## 逐屏复查结论

- **A1~A8**：无问题。省份名格式统一（简称），下钻匹配正常。
- **B1~B4**：无问题。
- **B5**：准备度饼图点击下钻映射语义错位（点"已导入"跳"已上线"单位；数据准备度 ≠ 上线状态）。轻微。
- **C1**：面板内"覆盖省份 34 省"为硬编码字符串。轻微。
- **C4**：`c4Stats` 中平均上线率 `String(launchedPct || 37.4)` —— **缺失时兜底一个编造的 37.4%**；
  "覆盖省份 34"硬编码。中等（编造数字，违反不造假）。
- **D1~D7**：无问题，防御与诚实标注最扎实（D5/D7 尤其严谨）。
- **E 屏（合规监督）**：`complianceUnits` 用 `row.id % 7`（审批越级）、`row.id % 11`（非工作时间大额操作）、
  `row.id <= 1000`（准备卡顿）等 **机械 id 规则派生合规风险标签** —— 属编造标签；注释残留"从 2000 家"。中等。
- **F 屏（风险研判）**：
  - `atRiskUnits` 同样用 `row.id <= 1000` 机械规则派生困难户（准备期卡顿）。
  - `insights.ruleBasedAlerts` 兜底写死过时假数字（"第六批 25 家""第七批 238 家""前五批 748 家""第八批 257 家"），
    数据扩充后早已不符；快照未提供时会展示这堆过时编造数字。中等。
  - F1/F2/F4/F5 无问题；F4 严守 KI-023/028 真实性门禁，做得好。

## 修复范围与策略

本 KI 修复"编造/硬编码兜底"这类可直接改的真实性问题：

1. **C4 上线率兜底**：去掉 `|| 37.4` 编造值，缺失时显示真实值或 `—`（沿用项目诚实缺失标注）。
2. **C1/C4 "34 省"硬编码**：改为从数据派生（省份去重计数），不写死。
3. **F3 ruleBasedAlerts 兜底**：移除写死的过时批次假数字兜底；无真实规则告警时显示中性空态，不编造。
4. **E/F 屏 id 机械规则造标签**：this 轮先消除最明显的编造项（`id % 7` / `id % 11` 造"审批越级/非工作时间大额操作"标签），
   改为仅依据真实指标（凭证率、建设进度、期初数据、状态）派生风险；`id <= 1000` 的"准备卡顿"判定改为
   依据真实 `batchId`（已推进批次的准备中单位）。注释"2000 家"更正为动态口径。

> 说明：E/F 屏"矛与盾"困难户识别的整体重构（引入更丰富的真实业务因子）范围较大，本 KI 先消除编造项，
> 深化可另立 KI。

## 完成定义
- C4 不再出现编造的 37.4%；C1/C4 省份数派生。
- F3 无过时假数字兜底。
- E/F 屏不再用 `id % N` 造合规/风险标签；`id <= 1000` 判定改用真实 batchId。
- `make check` 全绿；文档同步。
