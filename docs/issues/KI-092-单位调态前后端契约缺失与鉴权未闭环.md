# KI-092 · 单位调态前后端契约缺失与鉴权未闭环

- 状态：OPEN
- 优先级：P1
- 更新日期：2026-09-20
- 适用范围：单位调态 UI、治理写接口、身份与审计
- 来源：[KI-085 第 8、12 项](KI-085-核心架构缺陷与数据安全治理.md)、[KI-086 第 7 项](KI-086-中度隐患与数据库性能技术债务治理.md)

## 问题

[`frontend/src/composables/useEntityEditor.ts`](../../frontend/src/composables/useEntityEditor.ts) 会向 `/api/organizations/{id}` 发送 `PATCH`。后端现已存在对应路由并执行事务提交，但仍只有只读模式开关，没有调用者身份、授权上下文与服务端审计主体。前端 Store 仍预置两条静态审计记录，并在本地更新时继续生成“项目管理员”审计记录，容易被误认为真实服务端审计。

现有治理 `dispatch`、`enrich` 写接口只有只读模式开关，没有调用者身份与授权上下文。若产品保留任何在线写能力，后端契约、鉴权和审计必须一起闭环；若产品不需要写能力，应删除相应 UI，而不是保留半成品入口。

## 完成定义

- [ ] 明确选择“实现真实写入”或“删除调态入口”；
- [ ] 若实现写入，后端契约、事务、字段校验、身份认证、授权和审计主体完整；
- [ ] 若删除入口，前端不再展示可保存假象和静态审计记录；
- [ ] 轮询刷新后不会出现成功状态回滚或伪造审计；
- [ ] API、前端行为与安全回归测试通过。

## 2026-09-20 前端一致性治理

- 调态与组织分页请求已统一使用 `frontend/src/api/http.ts`，消除应用部署在子路径时的 API 地址分裂。
- 组织筛选请求会中止已过时请求，并用请求序号阻止旧响应覆盖新条件。
- C6 调态成功后同步当前分页行并后台刷新，避免 Store 与服务端分页列表显示不同事实。
- 上述工作只修复前端一致性，不代表鉴权、真实身份和服务端审计已经闭环，本 KI 继续保持 OPEN。

## 操作边界

本条目不授权创建生产写账号、执行 DDL、开放公网写接口或发布。
