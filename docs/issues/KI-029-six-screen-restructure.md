## 背景与目标
按 ADR-0007，将 7 候选屏收敛为 6 屏叙事，对齐观众三大关注（进度/风险/合规）+ 次线佐证，保持顶栏左右对称。
目标 6 屏：A 项目总览 / B 建设进度（含数据准备台账）/ C 上线推广 / D 风险预警 / E 合规监督 / F 业务运营。
URL 用序号路径 `/a`~`/f`，展示用中文名。

## 分工与拆分
### 轻量（主控执行）
- 导航收敛为 6 屏（左3 A/B/C + 中央标题 + 右3 D/E/F），`/data` 移出导航。
- 屏命名/定位调整：`问题清单`→`合规监督`、`智能研判`→`风险预警`（导航标签 + 页面标题）。
- URL 改序号路径 `/a`~`/f`；路由收敛；`/` 重定向到 `/a`。`/data` 路由暂留（内容合并前不删）。
- 每步 make check + 前端重建 + 线上验证；可回退。

### 重量（写 KI 派 agy，主控验收）
- B 建设进度：把 DataView（`/data` 建设推广项目台账）的台账检索/状态维护内容**并入** ConstructionView，
  内容搬不删；并入后 `/data` 路由与 DataView 方可退役（归档，遵守 ADR-0004 archive 不删）。
- E 合规监督：IssuesView 从"问题清单"转为"合规监督"视角——单位级合规概览（合规率约 92~96%、问题集中于困难户），
  可下钻到具体单位问题类型，不做逐笔会计级审计（依 BUSINESS-SIMULATION-ENGINE 第十四章）。
- D 风险预警：InsightsView 从"AI 研判"重心调为"风险预警"主场——突出"哪个单位要掉队"，与困难户/决策支撑咬合；
  展示层继续遵守 KI-023/KI-028（不展示未验证/不可信的模型指标）。
