# KI-042 · 灾难恢复能力不足与异机加密备份缺失

- 状态：OPEN
- 优先级：P0
- 更新日期：2026-09-07
- 关联：[已知问题看板](../KNOWN-ISSUES.md)、[数据与安全标准](../development/DATA-AND-SECURITY-STANDARD.md)、[KI-038 模拟器备份放大](KI-038-常驻模拟器重复全量备份导致磁盘耗尽风险.md)

## 结论

当前生产系统灾难恢复能力严重不足，存在不可逆数据灭失风险：
1. 托管数据库（Oracle Always Free MySQL HeatWave）仅具备默认 1 天自动备份，不支持 HA 高可用、只读副本、控制台手工快照及 PITR 任意时间点恢复。
2. 项目历史仅有一份 2026-09-05 的本地 SQL 导出文件，该文件位于生产主机本地根分区（单点依赖），未实现异机或对象存储灾备。
3. 缺乏定时导出、传输加密、多周期保留轮转及周期性恢复演练。一旦主机损坏或云租户故障，生产数据与历史演进无法恢复。

## 2026-09-07 现场证据

- 生产主机仅本地存有历史逻辑备份，未挂载或同步任何远程安全对象存储（如 OCI Object Storage / Cloudflare R2 / AWS S3）。
- 数据库无 PITR 配置，控制台无法执行热备份快照。

## 修复目标

- 建立自动化逻辑备份管线：每日定时执行完整/增量导出、压缩并加密。
- 异机灾备落盘：安全传输至离线/异地对象存储。
- 多周期保留策略与演练：定义 7 天/4 周保留机制，形成定期只读数据库恢复演练操作规程（Runbook）。
