## 结论

驾驶舱实时投影与常驻持久化模拟器目前是两套互不相干的随机事件系统。页面显示的是“数据库快照基数 +
独立进程内虚拟增量”，而不是模拟器真实提交事件的实时播报；文档却已经把目标态描述成落地态。该架构会让
页面数字、数据库事实、模拟剧情与治理事件无法勾稽，也造成两套节律、限额和单位选择逻辑长期分叉。

## 只读证据（2026-09-09）

1. `backend/app/live_projection/broker.py` 在模块加载时创建独立 `LiveProjectionBroker`，自行运行
   `RealisticSimulationEngine`、累计事件并广播 SSE；它没有消费 `mod-simulator` 的提交结果。
2. `LIVE-PROJECTION.md` 声称投影“不创建数据库连接”，但 broker 初始化会调用 `_load_units_pool()` 连接数据库。
3. 单位池只在 API 进程启动时读取一次；后续单位状态和新单位不会刷新。数据库读取失败被静默吞掉，并改用固定虚构单位。
4. `simulation_engine.py` 生成剧情标题、描述、金额、行业等级和 `friction_issue`，但
   `frontend/src/composables/useLiveProjection.ts` 只解析计数、单位和省份，丰富事件内容被丢弃，自愈摩擦也未进入治理链路。
5. 单位批次映射在 broker 中另写一套 CASE，和当前快照规范不完全一致；未来仍可能重现新增单位错批次。
6. 每日单据上限只在生成事件前检查，最后一个多单据事件可使累计值越界；累计状态仅在单进程内有效，
   API 重启或多实例时缺少续播、去重和一致性语义。
7. `BUSINESS-SIMULATION-ENGINE.md` 已写“播报内容即真实写入业务”，与上述代码事实相反。

## 影响

- 页面实时增量既不是数据库当前事实，也不是可稳定复现的预测，刷新或重启后难以解释。
- 同一单位可能被快照判断为一个阶段，又被旧单位池按另一阶段持续生成事件。
- 两套模拟器分别消耗维护成本，业务节律、批次映射、每日上限和风险故事会继续漂移。
- 文档把目标态写成已实现，接手者会基于错误架构认知继续开发。

## 修复边界与方向

1. 建立唯一事件源：持久化模拟器成功提交事务后生成不可变业务事件，由 SSE 只读广播该已提交事件；禁止提交前播报。
2. 使用事务 outbox、提交日志或等价的可恢复机制记录事件 ID、业务时间、单位、增量、来源和剧情；支持重连续播、去重与重启恢复。
3. 实时计数必须能与快照基数、数据库增量和事件累计勾稽；每日限额采用原子剩余额度截断，不能越界。
4. 删除独立随机单位/批次选择逻辑；单位与批次来自同一权威服务。数据库或模拟器不可用时显式显示实时流不可用，
   不得静默切换虚构单位并混入事实指标。
5. 前端消费并标识事件来源；若剧情和摩擦事件属于现行业务范围，应进入对应可见组件与治理链，否则停止生成。
6. 在完成合并前，文档必须如实标注双轨现状，不能继续声称“实时播报即真实落库”。

## 八、修改方法与实施思路（2026-09-12 补充）

### 8.1 当前已完成能力

经代码审计确认，以下能力已落地：
- 模拟器事务提交后追加 JSONL 日志（`output/committed_projection_events.jsonl`）
- `LiveProjectionBroker` 只读尾随 JSONL，不再独立生成随机事件
- 前端不再把会话脉搏叠加到数据库快照
- 每个 SSE 事件带唯一业务事件 ID
- 日/分钟事件上限由写入前原子预留控制

### 8.2 剩余未闭环项与修改方法

| 未闭环项 | 当前状态 | 修改方法 |
|----------|----------|----------|
| **断线重连续播** | 客户端重连从当前位置开始，历史区间丢失 | 客户端传递 `Last-Event-ID`，broker 从 JSONL 回放该 ID 之后的事件 |
| **跨实例消费者位点** | 单进程文件尾随，多 API 实例各自独立 | 改为数据库 outbox 表 + 消费者位点表，或使用 Redis Stream |
| **重启后续播** | API 重启后从 JSONL 末尾开始，历史丢失 | 同上，outbox 表持久化 + 位点恢复 |
| **提交与广播零窗口** | 文件追加与 broker 读取有微小时间窗口 | 可接受（毫秒级），如需严格一致可改为数据库触发器或 CDC |

### 8.3 实施步骤

**方案 A：基于 JSONL 的断线重放（低风险，推荐）**

1. **客户端传递 Last-Event-ID**
   ```typescript
   // useLiveProjection.ts
   const eventSource = new EventSource(`/api/live/projection?last_id=${lastEventId}`);
   eventSource.onmessage = (e) => {
     lastEventId = JSON.parse(e.data).event_id;
     // ...
   };
   ```

2. **Broker 支持从指定 ID 回放**
   ```python
   # broker.py
   def replay_from(self, last_id: str) -> Iterator[dict]:
       found = False
       for line in self._read_journal():
           event = json.loads(line)
           if found:
               yield event
           elif event.get("event_id") == last_id:
               found = True
   ```

3. **JSONL 定期轮转**（防止文件无限增长）
   ```python
   # journal.py
   def rotate_if_needed(self, max_size_mb: int = 10):
       if self.path.stat().st_size > max_size_mb * 1024 * 1024:
           self.path.rename(self.path.with_suffix(".jsonl.old"))
   ```

**方案 B：数据库 Outbox（中风险，适合多实例）**

1. **新建 outbox 表**
   ```sql
   CREATE TABLE sim_event_outbox (
       id BIGINT AUTO_INCREMENT PRIMARY KEY,
       event_id VARCHAR(36) NOT NULL UNIQUE,
       event_type VARCHAR(50) NOT NULL,
       payload JSON NOT NULL,
       created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
       INDEX idx_created (created_at)
   );
   ```

2. **模拟器写入 outbox**（与业务数据同一事务）
   ```python
   # simulation_writer.py
   def _write_outbox(self, conn, event: EventFootprint):
       conn.execute(text("""
           INSERT INTO sim_event_outbox (event_id, event_type, payload)
           VALUES (:id, :type, :payload)
       """), {"id": event.id, "type": "expense", "payload": json.dumps(event.to_dict())})
   ```

3. **Broker 轮询 outbox**
   ```python
   # broker.py
   def poll_outbox(self, last_id: int = 0) -> List[dict]:
       rows = conn.execute(text("""
           SELECT id, event_id, payload FROM sim_event_outbox
           WHERE id > :last_id ORDER BY id LIMIT 100
       """), {"last_id": last_id})
       return [{"cursor": r.id, **json.loads(r.payload)} for r in rows]
   ```

### 8.4 推荐路径

1. **短期**（方案 A）：基于现有 JSONL 实现断线重放，改动小
2. **长期**（方案 B）：如需多 API 实例负载均衡，迁移到数据库 outbox

### 8.5 授权需求

- 方案 A：仅代码改动，无需额外授权
- 方案 B：需要数据库 schema 变更授权（新建 `sim_event_outbox` 表）
