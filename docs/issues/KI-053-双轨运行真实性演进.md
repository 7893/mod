- **当前真库运行规模**：全网纳管单位共 **3,197 家**；其中第 6 批处于“双轨运行中”攻坚单位共 **333 家**；`dual_run_result` 底表累计沉淀 **32,077 笔**核对记录；
- **全链穿透勾稽打通（KI-066）**：驾驶舱 E 屏与 F 屏已通过 `backend/app/services/dashboard_sections.py` 引入 CTE 预聚合，派生各单位真实的凭证一致率（`voucherRate`），双轨核对不达标或差异风险已实时反映于大屏与下钻列表；
- **因果约束已在生命周期中生效**：`simulation/lifecycle_advancer.py` 中已落地“期初数据存在差异（`opening_diff_amount > 0`）时双轨考核天数强加 +7 天”因果惩罚。

## 演进方向评估与范围精简

在 2026-09-08 初建档时提出的 4 个候选方向，经过 **GI-004（矛与盾攻防态势与动态治理闭环）** 实施后，系统架构已发生重要跃升：

### 1. 【已在 GI-004 升维实现】双轨受阻 / 延期建模与工单拉锯
- **原设想**：在状态机内部针对双轨不达标单位设置倒退或显式计时惩罚。
- **GI-004 落地现状**：已在更高维度的**治理工单层**全面闭环——
  - `simulation/construction_propeller.py` 与 `simulation/governance_state_machine.py` 协同，当单位推进到 85%~90% 时自然触碰卡点暗礁，自动派生“票据异常·双轨月末记账凭证汇率与尾差不平”或“超期挂账”等高危/中危工单；
  - 触发工单期间，该单位生命周期推进与建设任务进度被完全冻结（`has_blocking_risk = True` 阻断跃迁）；
  - 调度 8 人专家池驻点排查，经历排查取证、发布补丁，并接受 **15% 严苛二次核验返工波折**；
  - 只有在工单完成闭环销项后，单位才解冻推进至“双轨运行中”，并触发下游真实凭证放量流水（E $\to$ B $\to$ C/D 跨屏涟漪）。
- **结论**：**本方向核心诉求（受阻、拉锯、波折、因果解冻）已由 GI-004 彻底实现，不再作为独立技术债跟踪。**

### 2. 【核心待办 · 方向 A】`dual_run_result` 差异原因语料化与穿透勾稽
- **现状分析**：当前 `dual_run_result` 表仅记录 `check_type`（3类）、`v1_amount`、`v2_amount`、`diff_amount`、`result`，缺少具体的业务差异原因列（`difference_reason`）。虽然 GI-004 治理工单层已有详尽的《处置单》故事文本，但底表记录与工单事由尚未做到逐笔语义级贯通。
- **演进方向**：
  - 为 `dual_run_result` 新增 `difference_reason`（差异原因分类与专业措辞）；
  - 注入符合真实央国资 ERP 割接质感的高保真语料：如“月末总账汇率截断时差”、“跨期预付账款挂账重分类”、“外币折算损益尾差（0.04元）”、“老系统凭证借贷科目单边调整”、“税率截断未结转”等；
  - 与 `governance_issue` 中的“票据异常”案情直接穿透对应。

### 3. 【核心待办 · 方向 B】双轨核对强度与一致率的财务周期波动
- **现状分析**：业务单据和凭证流水已在 `HongKongDiurnalEngine` 中具备逼真的月末（28~31日）、季度末及报税期集中放量节律；但底层 `DualRunCheckPlaybook` 生成不一致项仍为均匀静态抽样。
- **演进方向**：
  - 将双轨核对的执行密度与差异暴露概率接入自然月财务结账周期；
  - 在自然月 28~31 日结账攻坚期，核对单据量倍增，且由于新旧系统汇率结汇窗口或月末结转差异，不一致率出现温和脉冲，随后在次月初排查平账后回升，呈现真实的财务节律呼吸感。

### 4. 【储备待办 · 方向 C】脱离门槛分批 / 分行业差异化
- **现状分析**：当前脱离双轨门槛采用全局统一基准（持续 14 天、一致率 ≥ 98%、连续 3 次一致、持续达标 ≥ 7 天）。
- **演进方向**：未来可按行业/单位体量（如特大型制造重工 vs 轻资产科技分支机构）设定分层脱离门槛。由于当前统一标准已能较好支撑全网质量审计与合规勾稽，保持作为远期储备特性。

## 约束与规范

- **铁律坚守**：严格遵循“只进不退、跃迁留痕、第六批以外不产生双轨记录、全链勾稽 0 缺陷”。
- **门禁保护**：复用拟真引擎既有安全机制，未启用时维持 `MOD_SIMULATION_ENGINE_ENABLED=false` 失败关闭安全态，不影响线上 API 亚秒级响应（SLA ~40ms）。
- **同步更新**：任何底表变更或门槛微调同步更新 [DUAL-RUN-DEFINITION.md](../development/DUAL-RUN-DEFINITION.md) 与 [CURRENT-STATE.md](../CURRENT-STATE.md)。
