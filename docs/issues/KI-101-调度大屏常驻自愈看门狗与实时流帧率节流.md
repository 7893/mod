# KI-101 · 调度大屏常驻自愈看门狗与实时流帧率节流

编写日期：2026-09-17
- 状态：OPEN
- 优先级：P2
适用范围：实时投影与流式数据接入、大屏性能稳定性、展厅 Kiosk 模式、异常自愈

## 问题与证据

- **长周期常驻缺乏看门狗**：生产展厅与调度室大屏需要 7×24 小时无人值守常驻运行，目前前端缺乏对内存累积泄漏、未捕获 JS 致命崩溃以及 SSE/WebSocket 长连接隐蔽假死的自动化探测与自愈重启机制。
- **高频数据推送缺乏背压与节流**：当后端投影事件或模拟器高频推送事件时，前端直接触发响应式变化并驱动 ECharts 进行重绘，容易引起帧率波动（Jank）甚至瞬时卡顿，缺乏基于 `requestAnimationFrame`（RAF）的批处理缓冲合并。
- **动效状态分层不完善**：首屏入场动画与后续实时增量更新动画混杂，虽然部分组件手写了 `numDuration` 区分首屏，但缺乏全屏级别的动效状态机协同。

## 目标与方案

1. **实现前端调度大屏看门狗（Kiosk Watchdog）**：
   在 `frontend/src/composables/useKioskWatchdog.ts` 中实现：
   - 内存占用趋势探测（`performance.memory`）与超限预警；
   - 长连接健康探针与指数退避静默重连；
   - 严重白屏或未捕获致命异常捕获，在展厅夜间空闲时段或连续故障时自动重载刷新恢复。
2. **构建高频流 RAF 批处理与缓冲队列**：
   实现通用的 `useLiveStreamBatcher`，将密集事件缓冲合并，在浏览器下一次渲染帧统一派发更新，严格保障 60fps 流畅度。
3. **建立动效编排状态机**：
   明确区分 `InitialEntrance`（首屏入场特效）与 `IncrementalPulse`（增量实时微动效），杜绝常规刷新导致的全图反复入场跳跃。

## 修复范围与验收

- [ ] 实现 `useKioskWatchdog` 组合式函数并挂载于大屏顶层。
- [ ] 验证模拟断网及长时间运行场景下的自动重连与内存稳定性。
- [ ] 实现高频事件 RAF 批处理合并机制，高频推送下 Canvas 渲染保持 60fps 不丢帧。
- [ ] 完善首屏与增量更新动效分层，实时推送时无全局闪烁。
- [ ] 编写配套 Vitest 单元测试，并通过 `make check` 门禁。

## 边界

- 看门狗仅在前端环境安全执行探测与自愈，不修改后端健康检查与数据库状态。
- 不影响本地开发模式与常规调试流程。
