# KI-047 · Oracle 免费向量能力未利用与域内知识检索缺口

- 状态：OPEN
- 优先级：P3
- 更新日期：2026-09-08
- 适用范围：OCI MySQL HeatWave Always Free、项目知识资料的域内语义检索、KI-036 问答检索底座
- 关联：[KI-036 AI 业务数据洞察问答](KI-036-AI业务数据洞察问答.md)、[KI-045 HeatWave 内存集群未加载 MOD 表与加速失真](KI-045-HeatWave内存集群未加载MOD表与加速失真.md)、[ML/AI 数据边界](../development/ML-AI-DATA-BOUNDARY.md)、[数据与安全标准](../development/DATA-AND-SECURITY-STANDARD.md)、[HeatWave 使用与边界](../development/HEATWAVE-USAGE-AND-BOUNDARIES.md)

## 结论

生产 Oracle MySQL HeatWave Always Free 实例已经具备基础向量能力，但 MOD 当前没有向量字段、
Embedding 生成流程、语义检索表或 RAG 检索实现，KI、ADR、指标口径和操作手册仍只能依赖文件名、
目录或关键词人工查找。项目已支付的免费资源能力与 KI-036 所需的域内知识检索底座之间存在明确缺口。

2026-09-08 只读能力探测确认：

1. 生产实例版本为 `26.7.0-cloud`；
2. `VECTOR`、`STRING_TO_VECTOR()`、`VECTOR_DIM()` 可执行；
3. `DISTANCE(..., 'COSINE')` 可执行并返回正确结果；
4. `sys.ML_EMBED_ROW` 已存在；
5. 仓库当前未发现向量、Embedding 或 RAG 的实际接入代码与数据表。

Oracle 官方同时明确：Always Free 支持部分 HeatWave GenAI 能力，但**不支持托管 Vector Store**。
因此本问题不能按“免费版自动导入 PDF、自动切块并建立完整向量库”处理，只能在免费额度内建设
受控的小型 Embedding 表与相似度检索；不得把付费能力写进方案或验收口径。

## 影响

- KI-036 缺少可靠的语义召回层，模型只能接收预先拼装的数据，难以回答“相关规则在哪里”、
  “以前有没有类似问题”等跨文档问题。
- Known Issues、ADR、指标说明和运维手册之间的关联主要靠人工记忆，近义表述和自然语言提问难以命中。
- 若直接把整份文档或业务明细发送给外部 LLM，不仅浪费 Token，还会违反当前最小数据边界。
- 若误认为 Always Free 包含托管 Vector Store，实施人员可能设计出当前规格无法交付的自动摄取链路。

## 修复目标

在不升级付费规格、不引入外部知识检索、不泄露业务明细的前提下，建立一个可审计、可重建、
有来源引用的小型域内语义检索底座，为 KI-036 提供候选上下文，但不替代结构化 SQL 和 AutoML。

## 范围与非目标

### 纳入范围

- 首批仅摄取人工维护、允许用于知识检索的项目资料：KI、ADR、指标口径、前端设计规范和非敏感操作说明。
- 将资料按标题和语义段落切块，记录来源、版本、内容摘要、敏感等级和 Embedding。
- 使用 `ML_EMBED_ROW` 生成向量，并使用 `DISTANCE` 完成 Top-K 相似度检索；实现前须再次做最小权限与调用兼容性验证。
- 支持按资料类型、状态、模块和敏感等级先过滤，再计算向量距离。
- 检索结果必须返回来源标题、相对路径或稳定标识，供界面展示和答案引用。

### 明确不做

- 不给单据、凭证、人员、联系方式或逐条财务明细批量生成向量。
- 不用向量相似度计算金额、完成率、排名、对账结果或告警阈值；这些继续使用精确 SQL。
- 不用向量检索替代 HeatWave AutoML 的风险分类和业务量回归预测。
- 不依赖 Always Free 不提供的托管 Vector Store、自动文档摄取或付费向量索引能力。
- 不联网检索外部知识，不把“相似”解释为“事实正确”。
- 本 KI 不直接实现大屏问答交互；问答形态、缓存和模型输出仍由 KI-036 管理。

## 建议设计

### 1. 受控知识清单

建立显式白名单清单，只允许登记过的维护文档进入摄取流程。文件变更后按内容哈希增量重建，
文件删除或撤销授权时同步使相应分块失效，禁止扫描整个仓库、归档目录、环境文件或运行日志。

### 2. 最小向量表

建议使用单一职责表（最终名称由 Schema 设计评审确定），至少包含：

| 字段职责 | 说明 |
|---|---|
| 稳定标识 | 文档与分块的稳定 ID |
| 来源信息 | 类型、标题、相对路径、章节、状态 |
| 检索正文 | 经审查的分块文本 |
| 向量 | 与选定模型维度一致的 `VECTOR` 值 |
| 安全属性 | 敏感等级、是否允许送入外部 LLM |
| 版本属性 | 内容哈希、Embedding 模型、更新时间、是否有效 |

不在第一阶段拆出复杂多表体系，也不把大段重复正文写入多个表。Embedding 模型或维度变化时必须
可识别并全量重建，禁止混用不可比较的向量。

### 3. 查询链路

```text
域内问题
  → 输入长度与提示词注入检查
  → 结构化白名单过滤
  → 生成问题 Embedding
  → DISTANCE 检索 Top 5
  → 相似度门槛与来源去重
  → 返回原文摘要及来源
  → 可选：按 KI-036 的安全边界生成带引用回答
```

首期规模控制在约 500～3,000 个文本块，按普通距离计算验证价值，不把 ANN 或托管索引作为
免费层前提。只有实测延迟或规模确实成为瓶颈后，才另行评估架构与付费资源。

### 4. 数据边界

- 向量表及检索计算留在 OCI MySQL；数据库写入、DDL、批量 Embedding 生成必须另行获得显式授权。
- 当前 Cloudflare AI 边界只允许高度聚合、脱敏的数据。未经边界评审，不得把召回的任意文档片段
  直接发送到 Cloudflare AI Gateway。
- 第一阶段可只提供“语义搜索 + 来源展示”；若后续启用生成式回答，仅允许发送明确标记为
  “可供外部模型处理”的白名单片段，并同步修订数据边界文档。
- Prompt、Embedding 任务日志和错误响应均不得包含凭据、个人信息或未脱敏业务明细。

## 实施阶段

### 阶段 0 · 能力与权限定版

- 固化当前实例对 `VECTOR`、`DISTANCE`、`ML_EMBED_ROW` 的只读能力探测。
- 验证选定多语言 Embedding 模型、向量维度、单次与批量调用限制及最小数据库权限。
- 记录 Always Free 不支持 Vector Store 的官方依据，评审存储和计算上限。

### 阶段 1 · 离线小试

- 选择 500～1,000 个来自 KI、ADR、指标字典的安全文本块。
- 在非请求链路执行受限批量摄取；任务必须有批量上限、失败停止、可重跑和审计摘要。
- 只提供检索结果与来源，不接大模型生成。

### 阶段 2 · 质量验收

- 建立不少于 40 个真实问题的固定评测集，覆盖同义表达、跨文档关联、无答案、域外问题和注入攻击。
- 根据评测结果调整切块、过滤、Top-K 和相似度门槛，禁止通过模型补写来掩盖召回失败。

### 阶段 3 · 与 KI-036 集成

- 仅在数据边界评审通过后，把安全召回结果接入 KI-036。
- 生成结果必须带来源；低置信度或无来源时明确拒答。
- 沿用现有鉴权、限流、缓存、调用额度与降级策略，不新增无界后台任务。

## 完成定义

- 项目存在受版本控制的摄取白名单和可重复执行的切块规则，禁止宽泛扫描仓库。
- 生产向量表不包含人员、凭证、财务明细、凭据或其他禁止数据；有自动化敏感内容拦截测试。
- 固定评测集不少于 40 问，Top-5 来源召回率不低于 85%；无答案问题不得伪造来源。
- 所有域外问题和提示词注入用例均拒答；回答引用能够回到唯一维护来源。
- 3,000 个文本块以内的检索性能有实测记录和明确预算，不引入付费 Vector Store 依赖。
- 摄取任务具备幂等、批量上限、失败停止和版本重建能力；不得在大屏请求中同步批量生成 Embedding。
- 自动化测试覆盖：白名单、切块确定性、内容哈希、维度不匹配、Top-K 排序、来源过滤、
  无答案拒答、敏感数据阻断和外部模型发送边界。
- 数据库 DDL/DML、生产部署和外部 AI 调用均经过各自显式授权与验收；`make check` 全绿，
  `docs/CURRENT-STATE.md` 与相关现行边界文档在实现时同步更新。

## 剩余决策

1. 首批白名单是否只包含 KI、ADR 和指标字典，还是纳入部分设计规范与运维手册。
2. 选用的多语言 Embedding 模型、维度与模型升级后的重建策略。
3. 第一阶段只做语义搜索，还是在数据边界修订后直接接入 KI-036 的生成式回答。
4. 向量表使用独立最小权限账号还是扩展现有后台任务账号；不得复用公开 API 的可写账号。
