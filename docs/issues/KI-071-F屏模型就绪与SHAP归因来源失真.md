## 结论

F 屏当前仍违反“未生成、未验证、来源不明的智能结果不得展示为真实能力”的既有纪律：任一模型有效即可让整体
状态进入 Ready，但横幅固定宣称“2/2 模型可用”；HeatWave 解释缺失时，前端生成固定权重的规则解释，却继续
标成原生 SHAP；部分现场指标也由前端默认值补齐。该问题会把降级逻辑包装成数据库原生智能结论。

## 只读证据（2026-09-09）

1. `utils/modelEvaluation.ts::isAutomlReady` 在后端状态为 `READY` 且回归或分类任一模型有效时返回 true；
   `InsightsView.vue` 对 true 状态固定显示“独立测试集达标 · 2/2 模型可用”。
2. 模型质量行将质量值钳制到 `[0, 1]` 后再生成显示文字，负数回归 R² 会显示成 `R² 0.0000`，掩盖真实负值。
3. `AtRiskUnitTable.vue` 在解释接口失败或无归因时，前端自行生成 `48/32/20` 或 `52/30/18` 等固定权重；
   抽屉标题、加载文案和页脚仍宣称来自 HeatWave `ML_EXPLAIN_ROW` 与原生 SHAP。
4. `InsightsView.vue` 在单位预测不存在时，使用固定的停滞天数、推进斜率、培训错误剪刀差和经办人集中度，
   抽屉随后把这些值展示为“现场业务动量指标核验”；真实 `voucherRate = 0` 还会因真值判断被当成缺失值。
5. 解释请求错误被吞掉，没有“解释不可用/规则降级”的显式状态；快速切换风险单位时共用 loading 也可能产生错位。

## 影响

- 观众无法区分真实 HeatWave 模型输出、规则推断和前端占位数据，形成能力与数据来源误导。
- 同一 F 屏可能同时显示 `1/2` 模型就绪和“2/2 模型可用”，模型门禁自相矛盾。
- 负 R² 被美化为零，削弱独立测试集质量门禁的可信度。
- 后续基于风险解释采取治理动作时，可能把固定规则权重误认为 SHAP 因果证据。

## 修复边界与方向

1. 为每个模型分别返回并展示训练、验证、推理、解释能力状态；整体 Ready 不得推导出固定的 `2/2` 文案。
2. 模型指标保留原始数值与有效性判断，负 R² 如实显示；进度条可单独钳制，但不得反向污染文字值。
3. 风险解释响应增加来源枚举，例如 `HEATWAVE_SHAP`、`RULE_BASED`、`UNAVAILABLE`，并在前端显著区分。
4. 删除前端伪造的现场指标；缺值展示 `—/未提供`。规则解释若保留，必须使用真实输入、可追溯规则和“规则研判”标签。
5. 解释请求实现单位级缓存、请求隔离、失败态和重试，禁止旧单位结果覆盖当前抽屉。

## 完成定义

- [x] 负 R²、空值和异常值如实展示，质量文字不使用钳制后的伪值。
- [x] 只有真实 HeatWave 解释可使用 SHAP/`ML_EXPLAIN_ROW` 标识；规则降级和不可用状态来源清晰。
- [x] F 屏不再制造停滞天数、推进斜率、剪刀差、集中度或归因权重来填补接口缺失。
- [x] 增加解释失败、规则降级和请求乱序回归测试；模型计数与负值由类型/组件路径覆盖。
