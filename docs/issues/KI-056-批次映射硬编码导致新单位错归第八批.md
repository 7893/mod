# KI-056 · 批次映射硬编码导致新增单位错归第八批

- 状态：DONE
- 优先级：P1
- 更新日期：2026-09-08
- 适用范围：dashboard 快照的单位批次映射（C6 单位台账、批次矩阵与趋势面板）
- 关联：[KI-051 模拟数据规模扩充](KI-051-模拟数据规模扩充与真实勾稽.md)、`backend/app/services/dashboard.py`、`backend/app/services/dashboard_sections.py`

---

## 问题

C6「单位台账」面板的批次与省份筛选异常：**只有第八批有数据、前面各批次为空；选择省份后也无数据**。

## 根因

`build_entities`（`dashboard_sections.py`）与批次矩阵/趋势（`dashboard.py`，共两处）的 `batch_mapped`
CASE **按旧 2000 家单位的 id 区间硬编码**推断批次：

```
WHEN o.status='稳定运行' AND o.id<=150 THEN 1 ... WHEN o.id>1600 AND o.id<=2000 THEN 7 ELSE 8
```

KI-051 将单位扩到约 3,194 家（新增单位 id 2007~3193）。这些新单位的 id 落在所有旧区间之外，
被 `ELSE 8` 全部错归第八批；同时该逻辑几乎无视 `org_unit.batch_id` 真实批次。结果大量单位集中到
第八批，其它批次与省份筛选取不到数据。

## 修复（已执行）

三处 `batch_mapped` CASE 统一修正为：
- 双轨运行中 → 第六批；`batch_id = 8` → 第八批（优先判定）。
- **存量单位（id ≤ 2005）保留原有 status + id 区间映射**（对存量准确，不改变既有口径）。
- **新增单位（id > 2005）直接采用 `org_unit.batch_id` 真实批次**（`batch_id BETWEEN 1 AND 7 THEN batch_id`）。
- 其余兜底第八批。

## 验收证据（2026-09-08 实测 `/api/dashboard/snapshot`）

- entities 共 3,194，批次分布恢复正常：第一批 150、第二批 180、第三批 413、第四批 113、第五批 336、
  第六批 326、第七批 400、第八批 1,276（储备池较大，符合新增未启动单位多的真实情况）。
- 省份覆盖 34 个且均有数据（江苏、河南、广西、广东、陕西等）。
- C6 批次与省份筛选均可正常筛出单位。
