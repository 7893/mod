# KI-094 · 模拟审计日志完整性与容量失控

- 状态：OPEN
- 优先级：P2
- 更新日期：2026-09-17
- 适用范围：模拟器 JSONL 审计、并发写入、日志保留
- 来源：[KI-086 第 2、11 项](KI-086-中度隐患与数据库性能技术债务治理.md)

## 问题

[`simulation/simulation_writer.py`](../../simulation/simulation_writer.py) 与 [`simulation/construction_writer.py`](../../simulation/construction_writer.py) 都直接以追加模式写入 `output/simulation_audit.log`，没有统一的并发安全写入入口。该审计文件也没有轮转或容量上限，损坏或无限增长会同时影响审计可读性和磁盘空间。旧 `CommittedEventJournal` 已随 Outbox 收尾清理，不再作为解决方案依赖。

## 完成定义

- [ ] 所有审计写入使用一个明确的并发安全入口；
- [ ] 进程中断或异常记录不会破坏其他完整 JSONL 行；
- [ ] 配置轮转、保留周期和总容量上限；
- [ ] 解析器能跳过或隔离单条损坏记录并报告事实；
- [ ] 并发、截断恢复和轮转测试通过。

## 操作边界

本条目不授权修改生产日志、删除历史审计文件、重启服务或发布。
