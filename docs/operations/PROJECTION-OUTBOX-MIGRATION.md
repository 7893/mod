# 实时投影 outbox 切换与恢复步骤

更新日期：2026-09-13
状态：待执行
适用范围：KI-081 的生产 schema、权限、版本切换、验收与回滚

## 当前边界

本地代码已提供 outbox 写入、读取与清理；本文件是待审批的执行步骤，不表示生产已经迁移。
API/模拟器启动不会自动建表。缺少表或权限时，API 报来源不可用，快业务事务失败回滚，不能先部署新模拟器再补表。

## 上线前置

1. 另行获得目标库、DDL/DML、服务停止/启动及发布授权，核实目标实例和运行 release。记录当前模拟器进度、业务计数、JSONL 大小和摘要哈希，建立可恢复备份。
2. 在隔离的同版本 MySQL 验证 [schema 脚本](../../deploy/projection-outbox.sql)，检查两表为 InnoDB、sequence 主键、event_id 唯一索引、singleton_id=1 唯一状态行，核实新建表为空。脚本重复执行不得重置 stream_id/游标；`IF NOT EXISTS` 不代替已有同名表结构核验。
3. 验证两连接并发：事务 A 获取状态行锁、暂不提交；事务 B 必须等待。A 回滚后 B 使用回滚前序号，A 提交后 B 使用后续序号；读侧不得看见未提交事件。写者必须 `autocommit=False`。原理参考 [MySQL 锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。
4. API 账号仅需两表 SELECT。模拟器账号需事件表 SELECT/INSERT/DELETE、状态表 SELECT/UPDATE；DDL 由部署权限执行，不赋予 API。

## 切换步骤（均待授权）

1. 停止旧模拟器并确认无正在提交的事务。保留原 JSONL，记录最后事件 ID 和业务快照；不要导入旧日志为新 outbox 事件，不删除文件。
2. 在已核实的目标库应用 schema，检查初始状态、索引、引擎和权限。新 outbox 的累计从 0 开始，业务快照不清零。
3. 按项目发布门禁发布前端/API/模拟器一致版本。旧 EventSource 业务 ID 会收到显式 reset，新连接从当前 head 开始；这是标记过的切换边界，旧文件可离线追溯。
4. 启动模拟器，读取业务文档、outbox payload 中的业务事件 ID、持久 head/累计，核实同一批提交可相互勾稽。
5. 持有效游标断开、重启 API、重连，核实补发次序与业务 ID。两个客户端/两个 API 实例应收到相同持久记录；慢客户端暂停后恢复应分页补发或收到明确保留过期 reset。
6. 模拟数据库短暂不可用，验证事件流不推进游标、恢复后续播。确认写入失败整批回滚且没有 JSONL 兜底写入。验证定向回滚不能误操作真实业务，故障注入优先在隔离环境执行。
7. 检查只读轮询负载、连接池等待、锁等待和长连接表现；新读取池为每个 API 进程 4 连接，每客户端空闲轮询默认 0.5 秒。没有未经验证的水平扩展吞吐承诺。

## 保留和恢复

- 写入和前缀清理在同一事务；每次最多写/清理 1000 条，累计不因删除历史而下降。正常空表起步后行数上限 150000；过期 30 天前缀分批清理，无新增业务时不增长，也不运行后台删除。
- 保留期外不再承诺完整重放，返回 reset 并刷新快照。清理前如需长期审计应另行建立归档制度；outbox 不是永久业务审计库。
- 数据库从备份恢复或替换为另一个数据代际时，在切换窗口更换状态表 stream_id（需数据库写授权），让旧客户端明确 reset，不能复用可能对应其他业务的旧游标。
- 回滚前停止新模拟器/API，保留 outbox 两表和旧日志。若仅回滚前端，不影响 outbox 数据；若回滚到旧模拟器，它重新追加 JSONL，因此会形成新的、需要记录的切换边界，不能声称原子性仍然成立。禁止删除 outbox 以“恢复原状”。
