# MOD USA 数据库执行记录

版本：1.1  
状态：已执行并核验（2026-08-30）

> 文件名保留“待批准”是为了避免在未授权的情况下移动或删除历史文件；本文内容已经更新为实际执行记录。

## 一、执行结果

- 复用现有美国 MySQL HeatWave DB System，未为 MOD 新建 OCI 云资源。
- 建立独立逻辑数据库 `mod_s`，与现有 `modo_db` 完全隔离。
- 建立 24 张基础表和 6 个分析视图。
- 导入 2,034,212 条确定性 S 模式模拟数据。
- 数据库统一保存 UTC 时间，页面按 `Asia/Shanghai` 展示。

## 二、数据库账号边界

- `mod_bi_reader`：正式演示 API 使用，仅授予 `mod_s` 的只读查询权限。
- `mod_table_editor`：组件化路线验证时建立，仅允许维护指定项目管理小表；当前 NocoDB 已停止，不作为正式演示链路。
- 管理账号：仅用于受控建表、迁移、导入和数据修复，不写入应用代码。
- 所有密码仅保存在权限为 `600` 的 USA 环境文件中，不进入 Git 和本文档。
- 上述账号均不得访问或修改 `modo_db`。

## 三、导入和修复记录

1. 按外键顺序导入全部模拟数据，并逐表核对 manifest 行数。
2. 修正生成器中提交、审批、凭证生成、集成完成的时间公式。
3. 修正 CSV 导入器的 `CRLF` 行结束符处理。
4. 清理四个文本列中因首次导入残留的隐藏回车字符。
5. 保持全部表、主键及 2,034,212 条总量不变。

## 五、运行方式

- USA 项目目录：`/home/ubuntu/mod`，不覆盖 `/home/ubuntu/modo`。
- FastAPI 使用 `mod_bi_reader`，仅监听 `127.0.0.1:8100`。
- Nginx 通过 `/mod/api/` 反向代理 API，不开放 MySQL 公网端口。
- 当前公开 API 不包含 POST、PUT、PATCH、DELETE 写接口。

## 六、持续边界

- 不修改现有 MODO、`modo_db` 和其他 Nginx 路由。
- 不因 MOD 删除、缩容或修改任何 OCI 云资源。
- 删除或重建 `mod_s`、删除历史组件数据、创建 `mod_m/mod_p` 均需另行批准。
