# MOD 组件化实施基线（已终止的历史方案）

版本：1.1  
状态：已完成验证，2026-08-30 终止作为正式路线

> 本文仅用于保留 DataEase + NocoDB 路线的验证过程和决策依据，不再代表当前架构。当前正式演示路线为 Vue + 只读 FastAPI + HeatWave，见 `03-技术架构与实施计划.md` 和 `07-当前部署与运维基线.md`。

## 一、当时的方案原则

MOD 不再按完整自研业务系统建设。现有自研 Vue 和 FastAPI 代码冻结为设计验证资产，不继续扩张，也不删除。

当时拟采用的组件组合：

```text
NocoDB 社区版（在线台账）
        │ 仅允许维护项目管理小表
        ▼
美国 MySQL HeatWave / mod_s
        ▲
        │ 只读查询表和分析视图
DataEase 社区版（驾驶舱、地图、下钻、运营分析）
```

## 二、组件职责

### DataEase

- 领导驾驶舱、地图、筛选、图表和下钻。
- 复用 JPA 已有 6 个分析视图、5 个数据集和现有驾驶舱。
- 只使用只读数据库账号，不允许写业务表。

### NocoDB

- 单容器部署，SQLite 只保存 NocoDB 自身元数据。
- 连接美国 MySQL 外部数据源，作为接近 Excel 的在线台账界面。
- 仅展示和维护建设推广小表，不加载海量运营明细。
- 固定版本，不使用 `latest`；关闭遥测与外部支持聊天。

### MySQL HeatWave

- `mod_s` 是唯一业务数据库。
- 保存203万条模拟数据、人工维护小表和分析视图。
- HeatWave 只负责大规模查询加速，不承载页面和用户管理。

### 保留的自研内容

- 模拟数据生成器、持续增长脚本。
- 数据库表结构、分析视图和导入核验脚本。
- DataEase 自动配置脚本。
- 必要的数据质量检查 SQL。

## 三、数据库账号边界

### `mod_bi_reader`

- 供 DataEase 使用。
- 只授予 `mod_s` 的 `SELECT`。

### `mod_table_editor`

- 供 NocoDB 使用。
- 只允许读取基础字典。
- 只允许对以下项目管理表执行 `SELECT、INSERT、UPDATE`：
  - `rollout_unit_status`
  - `construction_task`
  - `data_readiness`
  - `opening_data_result`
  - `project_issue`
  - `project_risk`
- 第一阶段不授予 `DELETE`，避免误删记录。
- 不允许访问或修改单据、凭证、分录、集成结果等海量运营表。

### 管理连接

- 只在首次建表、导入和受控迁移时使用。
- 不写入 DataEase 或 NocoDB 配置。

## 四、USA 组件部署

- DataEase：复用当前 JPA v2.10.26 CE 方案，预计约 1.9 GiB 内存。
- NocoDB：固定 `2026.08.1` 单容器方案，实测约 0.56 GiB 内存。
- 两套组件总实测约 2.4 GiB，USA 现有约 23 GiB 内存足够。
- 两个服务都只监听 `127.0.0.1`，不直接开放公网端口。
- Nginx、域名和证书在数据库及组件验证成功后单独审批。

## 五、原计划实施顺序

1. 创建 `mod_s` 和两个最小权限账号。
2. 建立表和分析视图，导入203万条模拟数据并核验。
3. 在 USA 部署 DataEase，连接 `mod_bi_reader`。
4. 复建现有数据集和驾驶舱，核对与 JPA 结果一致。
5. 在 USA 部署 NocoDB，连接 `mod_table_editor`。
6. 创建建设推广、数据准备、问题风险的网格视图和表单视图。
7. 验证 NocoDB 修改后 DataEase 刷新即可反映变化。
8. 最后提交 Nginx、访问地址和认证方案供审批。

## 六、当时明确不做

- 不部署自研 FastAPI 和自研 Vue 作为正式系统（该条已被 2026-08-30 的后续决策取代）。
- 不引入 Redis、Kafka、ClickHouse、Kubernetes。
- 不购买 DataEase X-Pack 或 NocoDB 商业版。
- 不把 NocoDB 当作海量数据分析工具。
- 不允许任何新组件访问 `modo_db`。

## 七、验证结论

DataEase 和 NocoDB 已在 USA 完成部署验证，但最终未作为正式入口，主要原因是：

1. DataEase 默认登录流程不符合“打开即看”的演示要求。
2. 两个平台需要多个后台服务、元数据和连接配置，增加了当前阶段不必要的复杂度。
3. 领导驾驶舱、中国地图和项目表达需要更高的页面定制能力。
4. 已有 Vue 页面和 FastAPI 代码可以更快形成完整、轻量、可控的演示成果。

相关容器已停止但未删除，配置和数据保留；恢复或删除均需另行决定。
