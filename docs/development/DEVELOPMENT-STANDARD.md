# 开发规范

更新日期：2026-09-02
状态：现行
适用范围：MOD 的后端、前端、配置、依赖与兼容性变更

## 基本原则

- 先理解现有行为和测试，再修改代码；不以重写代替定位问题。
- 一次变更只解决一个明确目标，避免顺手修改无关代码。
- 依赖方向必须清晰：路由调用服务，服务调用领域或集成层，领域模型不得反向依赖 HTTP 层。
- 新代码进入已有领域目录；没有合适目录时先定义职责，不创建 `misc`、`utils2` 或根层散文件。
- 自研源码目标不超过 400 行，超过 600 行必须拆分或记录不可拆分原因。

## 后端

- Python 目标版本和依赖以 `backend/pyproject.toml` 为准，格式和静态检查以 Ruff 配置为准。
- 路由层只负责参数、依赖注入、状态码和响应编排；SQL 聚合与业务规则进入服务层。
- 外部平台访问进入 `backend/app/integrations/`，必须有超时、失败降级、数据边界和凭据隔离。
- 模拟器代码保留在 `backend/app/simulation/`，默认停用；不得绕过 `simulator_config.py` 的门禁。
- 捕获异常时保留可诊断信息，但不得把密码、Token、连接串、个人信息或原始业务明细写入日志。

## 前端

- 页面放在 `frontend/src/views/`，可复用组件放在 `frontend/src/components/`，复用状态逻辑放在
  `frontend/src/composables/`，共享状态放在 `frontend/src/stores/`。
- TypeScript 类型应表达接口契约；避免新增无边界的 `any`，接口字段变化必须同步后端和测试。
- 全局 CSS 入口只组织导入；基础、组件、页面和响应式规则分别放在 `frontend/src/styles/`。
- 不直接修改 Element Plus、ECharts、依赖包或生成产物；通过源码导入和构建配置优化。

## 配置与依赖

- 配置统一来自环境变量、配置模块或受控静态配置，不得硬编码主机、密码、Token 或生产连接串。
- 新环境变量必须同步 `.env.example`、读取代码和相关文档，示例值不得是真实凭据。
- 依赖变更必须说明用途，使用对应包管理器更新清单与锁文件，不手工伪造锁文件。
- 未涉及依赖时不得产生无关锁文件变更。

## API 与兼容性

- 已公开路由、字段、状态码和导入路径默认保持兼容；破坏性变更必须明确获批并记录迁移方式。
- 兼容门面应保持小型，仅转发稳定接口；新代码直接引用新的领域模块。
- 数据库不可用、模型未训练或外部 AI 关闭时必须如实降级，不得生成伪造的成功结果。

## 完成定义

代码、测试、当前文档、示例配置和部署资产必须彼此一致；通过 `TESTING-STANDARD.md` 规定的检查后，
变更才算完成。
