# 协作规范

更新日期：2026-09-02
状态：现行
适用范围：人类开发者、Codex、Claude、Kiro、agy、Copilot 及后续接入的编码 Agent

## 接手

1. 阅读 `AGENTS.md`、`CONTRIBUTING.md` 和 `docs/CURRENT-STATE.md`。
2. 检查 `git status`、当前分支和相关差异，确认哪些改动已经存在。
3. 阅读目标模块、测试和**与任务类型匹配的现行规范**（见 `AGENTS.md` 的"Required reading by task type"映射表：
   改前端读前端规范、碰数据库读数据安全规范、任何改动读测试规范等），不从历史交接提示词推断当前事实。
4. 明确任务范围、验收条件、危险操作和需要保留的兼容行为。

## 派单方责任（派活给执行 Agent 时）

- 派单必须在开头要求执行方"先读 `AGENTS.md` 及本任务类型对应的领域规范"（依上表），把执行方导向入口，
  而非在派单里逐条重抄规范。领域规范是唯一事实源，派单只做任务说明与该任务特有的约束/验收。
- 派单需注明：任务范围、必读文档、硬约束（含该领域规范）、验收标准、分工与提交要求。

## 工作期间

- 用户已有改动属于用户；不得覆盖、回滚、格式化或顺手提交无关变化。
- 多人或多 Agent 协作时按文件或领域划分所有权，避免同时编辑同一文件；发生重叠先协调。
- 临时脚本遵守 `CLI-SCRIPT-POLICY.md`，不得借用其他执行者目录。
- 优先执行只读核查和可逆操作。数据库写入、生产变更、云操作、删除和对外发布必须在授权范围内。
- 发现事实冲突时以现行源码、测试、部署配置和实际只读检查为证据，并修正当前文档。
- 不恢复、不运行、不维护已归档至 `archive/legacy-collaboration/` 的历史协作状态机。

## 沟通

- 先报告结论和影响，再说明必要技术细节。
- 假设必须明确；会改变任务方向、数据或生产状态的假设不得自行执行。
- 阻塞时说明已经验证的事实、具体阻塞条件和需要的最小决策，不只报告“无法继续”。
- 不把未验证的推测写入 `CURRENT-STATE.md` 或当作交接事实。

## 交付与交接

交付必须包含：

- 实际完成内容和未完成内容。
- 修改过的架构、接口、数据或部署状态。
- 执行过的检查及结果。
- 已知风险、回滚或恢复位置。
- Git 工作区状态和签名提交 ID。

不得仅交付聊天中的说明；会影响后续维护的事实必须进入对应当前文档。
