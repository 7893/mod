# 双轨运行与脱离双轨定义

更新日期：2026-09-08
状态：现行
适用范围：业务系统建设推广中"双轨运行（Dual-Run）"的业务定义、进入/脱离条件与拟真引擎实现
关联：[拟真引擎业务规范](./SIMULATION-PIPELINE-SPEC.md)、`simulation/lifecycle_advancer.py`（状态机与门槛）、

> 术语澄清：本文所述为"双轨"（Dual-Run，新旧系统并行运行），与纪检术语"双规"无关。

## 一、什么是双轨（Dual-Run）

**双轨运行**指一个单位在从旧系统（或手工账）切换到新系统的过程中，**新、旧两套系统在同一业务期间并行运行、
同时处理同一批真实业务，并对两套账本的结果逐笔比对**的过渡阶段。

- **目的**：在正式依赖新系统前，用旧系统作为"对照真值"，验证新系统的数据准确性与业务连续性，
  把切换风险降到最低。不是"试用"，而是"新旧同时真实记账并逐笔核对"。
- **核对内容**：新老两套账对同一业务执行 **单据金额核对、凭证借贷汇总核对、月末科目余额比对**
  （见 `construction_playbooks.py::DualRunCheckPlaybook` 的 `check_type`），记录每次核对的一致/不一致
  与差异金额（落库 `dual_run_result`）。
- **关键指标**：双轨一致率（一致笔数 / 总核对笔数）、连续一致次数、核对累计笔数、双轨运行天数。

在本项目的单位生命周期状态机中，双轨是一个**独立阶段**：

```
未启动 → 准备中 → 已具备双轨条件 → 双轨运行中 → 已上线 → 稳定运行
                                  └─ 本阶段即"双轨运行"
```

- **进入双轨（已具备双轨条件 → 双轨运行中）** 的前置门槛（`lifecycle_advancer.py`）：
  - 培训通过率 ≥ 90%（关键用户具备操作能力）；
  - 在"已具备双轨条件"状态持续达标 ≥ 3 天。
- 进入前还须满足更早的数据准备门槛（静态/期初数据 100%、期初差异为 0、动态同步率 ≥ 90%）。

## 二、什么是脱离双轨（Exit Dual-Run）

**脱离双轨**指一个单位经过一段时间的双轨并行核对，**新系统数据被验证为持续准确、可信、可独立承载业务后，
停止旧系统的并行记账，正式以新系统作为唯一生产系统**的跃迁。在状态机中即：

```
双轨运行中 ──（满足脱离条件）──→ 已上线
```

"脱离双轨"= 单位从"双轨运行中"跃迁到"已上线"。此后旧系统退出，新系统单轨正式运行。

### 脱离双轨的硬性条件（`lifecycle_advancer.py` 实测门槛）

一个单位要脱离双轨（转入"已上线"），必须**同时**满足以下全部条件：

| 条件 | 阈值 | 说明 |
|---|---|---|
| 双轨运行天数 | ≥ 14 天（`dual_run_days_min`） | 期初数据存在差异（`opening_diff_amount > 0`）时**+7 天惩罚**，即需 ≥ 21 天 |
| 双轨核对累计笔数 | ≥ 5（`dual_run_min_checks`） | 核对样本量足够 |
| 双轨一致率 | ≥ 98%（`dual_run_consistency_rate_min`） | 新老账逐笔比对一致率 |
| 最近连续一致次数 | ≥ 3（`dual_run_consecutive_matches_min`） | 近期稳定一致，非偶然达标 |
| 无阻断性风险 | 必须（`has_blocking_risk = False`） | 无未闭环的阻断性业务差异或高危风险 |
| 持续达标天数 | ≥ 7 天（`dual_run_consecutive_days_min`） | 上述指标须连续达标，非单日达标 |

- **只进不退**：跃迁只向前，不允许从"已上线"退回"双轨运行中"（状态机三条铁律之一）。
- **跃迁留痕**：每次脱离双轨都生成《专家组上线评审决议书》足迹（`TransitionReviewPlaybook`），
  写入 `rollout_status_snapshot` 带评审留痕，可追溯。
- **因果真实性**：期初数据质量差的单位（有期初差异）脱离双轨更慢（+7 天），体现真实的"底子差、
  切换更谨慎"因果，而非机械计时。

## 三、项目中的实现现状

脱离双轨**已在拟真引擎中实现并运行**：

- **状态机推进器** `simulation/lifecycle_advancer.py`：`_check_transition_qualification` 对"双轨运行中"
  单位逐日评估上述六项门槛，全部达标且持续 ≥ 7 天才跃迁到"已上线"，否则给出不达标原因。
- **双轨核对数据** 落库 `dual_run_result`（核对类型、新老金额、差异、一致/不一致、核对日期），
  由 `DualRunCheckPlaybook` 生成（仅限第六批双轨攻坚单位，严禁在其他批次产生双轨记录）。
- **跃迁评审留痕** 由 `TransitionReviewPlaybook` 生成专家评审决议，随跃迁写入快照。
- **大屏展示**：驾驶舱以"双轨运行中"单位数、双轨一致率、双轨核对量等指标呈现全网双轨攻坚态势
  （如 C1/C屏推广状态、D屏双轨核对面板）。

### 演进方向（系统是活的）

本项目是持续演进的真实拟真系统。双轨相关可继续深化（登记为后续 KI 再实施，不在本文档强行扩张）：

- 双轨阶段的**回退/异常**建模：真实中若双轨期发现重大不一致，可能延长双轨甚至暂停上线；当前状态机
  为"只进不退"，未来可评估是否引入"双轨受阻→延期"的显式建模。
- 脱离双轨门槛的**分批/分行业差异化**：不同批次、不同规模单位的脱离标准可差异化，更贴合真实推广节奏。
- 双轨一致率的**周期性波动**：结合月末结账等财务周期，双轨核对强度与差异呈现真实节律。

## 四、口径与勾稽

- "双轨 N 家"指当前处于"双轨运行中"状态的单位数（本项目主要为第六批攻坚单位）。
- 全网勾稽：总纳管 = 各状态单位之和；双轨单位数计入总纳管，不重复计入已上线。
- 任何涉及双轨口径、脱离双轨门槛的改动，须同步更新本文件与 `CURRENT-STATE.md`。
