# 文档规范

更新日期：2026-09-02
状态：现行
适用范围：项目说明、开发规范、运维记录、证据、任务书和历史材料

## 文档分类

| 目录或文件 | 用途 | 是否代表当前事实 |
|---|---|---|
| `README.md` | 项目概览和快速入口 | 是，但只保留稳定概要 |
| `docs/CURRENT-STATE.md` | 当前运行、数据、功能、风险和边界 | 是，最高事实入口 |
| `docs/development/` | 现行开发、协作、测试和文档规范 | 是 |
| `docs/operations/` | 当前部署规则及带日期的运维记录 | 视文档状态而定 |
| `docs/evidence/` | 脱敏、不可改写的验收证据 | 证明当时事实 |
| `docs/tasks/` | 当前或历史执行任务书 | 不能替代当前状态 |
| `archive/legacy-collaboration/` | 已归档的停用状态机和历史交接 | 否，只读历史 |
| `archive/` | 历史实验和本地工作台 | 否 |

## 新文档格式

现行文档必须包含标题、更新日期、状态和适用范围。推荐头部：

```text
# 标题

更新日期：YYYY-MM-DD
状态：现行｜草案｜历史｜已停用
适用范围：...
```

文件名使用清晰稳定的主题名（英文大写，如 `FRONTEND-ARCHITECTURE-AND-CONSTRAINTS.md`）。
新规范放入 `docs/development/`，新运维规则放入 `docs/operations/`；
不要继续扩展旧编号文档体系，也不要在项目根目录新增零散说明。

**语言规范：文档内容默认使用中文；仅在"必要"时使用英文。**
"必要"的定义：
- AI agent 约定入口文件（`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`）内容用英文（大模型对英文指令执行更稳定）
- 对外门面文档（`README.md`）用英文（GitHub 访客与开源惯例）
- 文件名始终用英文大写（路径稳定、跨平台兼容）
- 专业术语（ADR、Blast Radius、Diátaxis 等）在中文文档中可保留英文原文
- 其余所有文档正文、标题、章节名一律中文

## 事实与更新

- 行为、接口、目录、命令、数据状态或部署状态改变时，同一任务内更新相关当前文档。
- `CURRENT-STATE.md` 只写已验证事实；计划、猜测和讨论进入任务或设计文档。
- 历史文档保留原貌。发现过时内容时，在当前文档纠正或给历史文档增加明确状态说明，不篡改证据。
- 文档引用命令、路径、URL、服务名、数据库名或测试数量时，必须从当前代码或只读检查核实。
- 使用相对仓库路径链接项目文件，避免依赖某个编辑器的私有链接格式。

## 安全与质量

- 禁止写入密码、Token、私钥、完整连接串、Cookie、真实个人信息或可复用认证材料。
- 日志和证据入库前必须脱敏；大体积原始输出留在忽略目录，只提交必要摘要。
- 删除或迁移文档后更新 `docs/INDEX.md` 和所有活动入口，避免孤立链接。
- 文档必须区分“已执行”“计划执行”和“需要授权”，不得把计划描述成完成事实。

## 审阅清单

- 事实是否与 `CURRENT-STATE.md`、源码、测试和部署配置一致。
- 状态、日期和适用范围是否清楚。
- 是否放在正确目录并加入索引。
- 是否存在过时路径、旧数据库名、旧服务或历史状态机指令。
- 是否泄露敏感数据，是否错误承诺未执行的操作。
