# 协作机制与文档治理:标杆对照与演进方向

更新日期：2026-09-06
状态：现行（架构阐释 / Explanation 类长青文档）
适用范围：文档组织方法论、协作约束体系、对标业界典范的演进方向

本文属 Diátaxis 四象限中的 **Explanation（架构阐释）**：解释"我们的协作与文档体系为什么这样组织"，
不含具体操作步骤（操作见各领域 standard）。它是长青参考，随体系演进增补，不记录易碎的瞬时数字。

## 一、业界典范怎么做

- **Diátaxis 四象限**：文档按读者心智分四类，不混在一篇里——
  Tutorials（学习）、How-To（任务）、Reference（信息，尽量代码/Schema 派生）、Explanation（理解/为什么）。
- **RFC / PEP / ADR**：重大改动先提案（动机、替代方案、兼容性、风险）；决策采纳后 **ADR 只增不改、编号递增**，
  推翻旧决策时新增一条并标注 `Supersedes ADR-xxxx`，让"当初为什么这么选"可追溯。
- **机制压倒自觉（Google）**："没有被工具/闸门机制化的规则，等于不存在。"格式、风格、密钥、提交规范一律在
  动作点（IDE → pre-commit → CI → 发布）自动阻断，不靠人工 review 纠结。
- **Docs-as-Code + 单一事实源（SSOT）**：凡能从代码/Schema 派生的绝不手写；文档纳入 CI（术语校验、链接检查、
  Doc Impact）。手写的易碎数字是文档腐化的主要来源。

## 二、MOD 现状（对照标杆）

已建立的机制基石（属典范级实践）：
- 协作范式：主控把关派单 + 契约约束 + 动作点硬闸门；派单指引读领域规范，规范是唯一事实源、不重抄。
- 脚本目录硬隔离（`CLI-SCRIPT-POLICY.md`）；根目录零散落脚本。
- 四大硬闸门（`ENFORCEMENT.md`）：A 凭据扫描、B 数据库写操作五步纪律、C 提交前 make check + 提交信息校验、
  D 同机生产感知。
- 前端三层契约（骨架/物料 CockpitPanel/Token）；自研源码 ≤400 行；单一正统命名（无 `_v2/_v3`）。
- 活/死文档分类（`DOCUMENTATION-LIFECYCLE.md`）：活文档单一真理强制同步，死文档（ADR/history/CHANGELOG）只增不改。
- 按任务类型读规范的映射表（`AGENTS.md`），CI 五道闸门（scan_secrets / validate_commit_message /
  lint_frontend_arbitrary_values / check_doc_sync / make check）。

## 三、演进方向（对齐标杆，取"真高效"，不为完美而完美）

推进与取舍见 `docs/issues/KI-030-协作机制与文档治理演进.md`。摘要：
1. 文档"最后一公里"收敛：`docs/` 顶层编号文档 23-28 语义化归位（现行进 development、历史进 history），
   顶层仅留三大活文档 + 分类子目录。（做）
2. 事实派生自动化：活文档正文只记"基线与口径"，动态绝对数字（行数/人数等）改由只读派生脚本按需提取，
   消除手写数字漂移。（做）
3. 提交"事实影响声明"从软警告向结构化契约进化：**评估后暂缓**——强制每次声明影响类型会增摩擦，
   先观察 `check_doc_sync.py` 软警告是否足够。
4. 多 Agent 上下文降噪 + 作用域锁定：按需加载规范（已由映射表实现）；开工前声明目标文件集合（Blast Radius）
   由主控错峰派单，防并发冲突。（轻量补入协作规范）
5. 同机生产的软链发布隔离：本地构建输出到私有目录，Nginx 伺服指向 `releases/<ts>` 的软链，
   授权后原子切换，从物理上杜绝"构建即击穿生产"。（做，最高价值）

## 核心原则
将工程从"依靠人的自觉"推向"依靠体系、契约与动作点自动闸门"。文档是活的（当前归当前、保持准确），
历史是留痕的（决策与演进可追溯、只增不改）——两者分工，都服务于"让做对事最省力"。


## 四、KI 与需求的三角闭环模型

两者本质不同，严禁混淆：

| 维度 | 已知问题（KI / Bug） | 需求（Feature / Task） |
|---|---|---|
| 本质 | 现状与预期的**负差**（系统做错了/有漏洞） | 系统能力的**正向增量**（系统原来没有） |
| 目标 | 消除偏差，恢复基线 | 设计落地，提升基线 |
| 载体 | `docs/KNOWN-ISSUES.md` 看板 + `docs/issues/KI-xxx.md` | GitHub Issues（feature_request / task 模板） |
| 终点 | 修复 + 补回归测试 + 关闭留痕（永不物理删除） | 代码合入 + 更新活文档 + CHANGELOG 记录 feat |

**决策取舍用 ADR**：凡影响架构、数据安全、流程边界的重大决策，新增 `docs/decisions/ADR-xxxx`；
被推翻时新增一条并标注 `Supersedes ADR-xxxx`，旧件保留可追溯。

**终点回写（拒绝"只关 issue 不更文档"）**：任何改变了数据规模、API 路由、页面布局、部署端口等事实的提交，
必须在同一次提交内更新 `docs/CURRENT-STATE.md` 和对应现行规范；未同步的提交视为未完成。
