# MOD V2 动态刷新与无刷新轮询机制说明

- **版本**：2.0
- **基线日期**：2026-08-30
- **维护角色**：Google Antigravity / agy
- **适用系统**：MOD 领导驾驶舱前端与只读 API

---

## 一、设计目标

在大型数字化管控大屏展示中，必须同时满足**平滑无感的实时数据刷新**与**极高可用性的容错保障**：
1. **零整页刷新**：前端采用 Pinia Store 异步 API 轮询机制，更新仅局部触发 Vue 响应式 DOM 重渲染，ECharts 图表通过 `autoresize` 与 reactive `option` 平滑过渡，禁止页面级 F5 刷新。
2. **轻量与防风暴**：默认轮询周期为 **60 秒**；后端快照接口设立 60 秒内存 TTL 缓存，避免大规模并发请求冲击只读数据库连接池。
3. **快照保持（降级容灾）**：若在运行过程中发生瞬时网络中断或后端服务抖动，前端**严禁自动回退为随机 Mock 数据或空白白屏**，而是严格**保持上一次已成功获取的有效快照**，并弹出非阻塞式状态横幅提示。

---

## 二、刷新机制架构

```text
[浏览器大屏前端 (Pinia Store)]
       │
       ├─ (1) 页面初始化: 加载本地内置 v2-sim-snapshot.json 确保首屏 0 延迟秒开
       │
       ├─ (2) 触发定时器: 每 60,000 ms (60s) 调用 GET /api/v2/dashboard/snapshot (silent=true)
       │       │
       │       ├── [HTTP 200 成功] ──> 更新 snapshot.value 与 entities.value
       │       │                       更新 lastLoadedAt = new Date()
       │       │                       清除 connectionError
       │       │
       │       └── [网络中断/5xx 异常] ──> 保持当前 snapshot.value 不变
       │                                  设置 connectionError = "数据刷新受阻..."
       │                                  界面显示非阻塞警告条，保留历史图表
       │
       └─ (3) 用户手动刷新: 点击顶栏刷新图标立即发起非静默请求，显示微旋转动画
```

## 三、接口设计与轻量元数据

### 1. 主快照接口：`GET /api/v2/dashboard/snapshot`
- **缓存控制**：`Cache-Control: no-store`（避免浏览器 HTTP 层旧缓存），由后端应用层维护线程安全的 TTL（60s）缓存。
- **字段转换**：前端内置 `fixKeys` 递归函数，自动将服务端 snake_case 转换为前端标准的 camelCase。

### 2. 轻量刷新元数据接口：`GET /api/v2/dashboard/refresh-meta`
- 返回轻量级 JSON，用于微前端或低频监测：
```json
{
  "data_version": "v2.0-frozen",
  "as_of_date": "2026-08-30",
  "last_updated_at": "2026-08-30T16:00:00",
  "total_rows": 1685923,
  "status": "ok",
  "seed": 42
}
```

## 四、界面展示元素

1. **顶栏数据截至日期**：展示 `数据截至 2026-08-30`，明确当前宏观指标的数据业务口径基准。
2. **上次刷新时间**：展示 `更新于 HH:mm:ss`，直观呈现最近一次与服务端通信成功的时间点。
3. **非阻塞错误提示**：当连接发生异常时，顶栏下方弹出淡橙色提示条 `【快照保持模式】数据刷新受阻，当前维持上一有效快照`，并提供 `重试连接` 按钮。
