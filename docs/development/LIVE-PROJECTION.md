# 驾驶舱只读实时投影

更新日期：2026-09-13
状态：现行
适用范围：驾驶舱演示动态、实时事件接口和增长展示约束

## 2026-09-13 · KI-081 当前实现（本地完成后待部署验收）

本节取代下文“目的与边界 / 数据流 / 增长约束 / 配置与运行”的 JSONL 运行描述，原文保留供追溯。

- 模拟器快业务写入在原连接、原事务内调用 `append_outbox`，将业务数据和 `sim_event_outbox` 原子提交。`sim_event_outbox_state` 单行 `FOR UPDATE` 锁保护持久序列与累计量，直至外层 commit/rollback。没有独立 outbox commit、运行时建表或 JSONL 回退。
- API 使用独立的小型只读连接池读取 outbox；连接/读写 socket 与连接池等待各有 3 秒上限，查询移入线程，避免阻塞异步事件循环。不导入模拟器、不执行 DDL/DML。
- `/api/live-projection/events` 每个连接使用独立游标，单次最多读取 100 条；不再用队列丢弃慢客户端事件。`id=outbox:<stream_id>:<sequence>` 是持久游标，`business_event_id` 保留原 document-ID。既有业务字段与事件类型保持兼容。
- 无 Last-Event-ID 的新连接从读取时的 head 开始，已有业务由快照承载；这不是恢复消费位置。有效 Last-Event-ID 的重连从该序号之后续播，不先发最新 head 状态，不改变其他客户端累计值。累计来自写入时的持久累计，前端仍禁止叠加到数据库快照。
- 保留边界外、未来位点、旧 JSONL ID 或代际不匹配的游标返回 `projection_state`，明确 `reset_required/reset_reason` 并将游标定位当前 head；前端刷新权威快照。临时数据库故障发送不含 id 的 `source_unavailable` 事件，保留原游标并重试。
- 序号/累计跨 API 重启保持稳定；多个 API 实例各自读取相同持久记录，不共享一个会吞掉其他客户端事件的消费位置。交付承诺是保留范围内至少一次与前端序号去重，不是无限历史、端到端恰好一次或无条件零丢失。
- 每次写事务最多 1000 条，并清理最多 1000 条过期前缀。默认保留上限 150000 条，30 天为分批清理期限；长时间停机后的过期记录随后续写入逐批回收，不由只读 API 清理。持久 `pruned_through` 让慢客户端能识别清理缺口。
- `journal.py` 及旧 JSONL 只保留作历史工具/归档，当前运行链路不再调用。既不自动删除旧日志，也不将旧事件重新插入为新业务。

迁移脚本、权限、恢复演练和验收见 [outbox 切换步骤](../operations/PROJECTION-OUTBOX-MIGRATION.md)。生产建表、切换和 MySQL 锁行为验收尚未执行，不能据本地代码宣称线上已完成。


## 目的与边界

实时投影让持续开启的驾驶舱播报常驻模拟器已经提交的单据、凭证和集成事件。API 只读尾随
`output/committed_projection_events.jsonl`，不创建数据库连接、不写业务表、也不再运行独立随机模拟器。

数据库快照始终是累计数字的唯一事实源；SSE 累计值只表示当前 API 会话已看到的提交脉搏，前端禁止将其
叠加到快照总量。日志不存在时状态接口明确返回 `source_available=false`，不得切换到固定虚构单位池。

## 数据流

```text
模拟器事务 COMMIT -> 持久提交日志 -> 只读 SSE broker -> 前端会话脉搏
数据库只读快照 --------------------------------------> 前端累计指标
```

- `/api/v2/dashboard/snapshot` 继续按原周期提供真实基数。
- `/api/v2/live-projection/events` 向所有在线大屏广播同一事件时间线。
- `/api/v2/live-projection/status` 提供不产生事件的只读诊断状态。
- 浏览器将快照事实和服务端会话脉搏分开保存，绝不相加。
- `projection_id=committed-simulator`；序号只用于当前 API 会话内去重。API 启动时从日志末尾开始，
  旧记录已进入数据库快照，不重放、不重复计数。

## 增长约束

- 到达节律、单位选择和每日上限全部由唯一常驻模拟器控制，broker 不再拥有第二套规则。
- 日志记录包含唯一业务事件 ID、提交时间、单位、批次、金额、增量和结果摘要；只有事务提交成功后才能追加。
- SSE 只承载日志中的共同事件，禁止浏览器或 API 进程独立随机修改累计值。
- 队列有容量上限，慢客户端只保留较新的展示事件；重连时先接收服务端累计状态。

当前阶段不使用历史硬编码的 2027-03-01 目标值。长期目标曲线必须先根据当前数据库基线和新的业务目标
重新确认，之后才能作为可配置速率因子加入本投影。

## 配置与运行

`MOD_LIVE_PROJECTION_ENABLED` 默认为 `true`，设置为 `false` 可停止日志尾随；它不改变写库模拟器门禁。
`MOD_LIVE_PROJECTION_JOURNAL_PATH` 可覆盖提交日志位置，默认与运行主机 `output/` 目录一致。

当前日志尾随适用于同机单 API 进程。多 API 实例需要共享 outbox/broker 与消费者位点后才能启用，不能
通过每实例独立尾随来声称具备完整重连续播语义。
