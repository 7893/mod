# ADR-0023 · 清空存量 KI 并按当前复现重新登记

更新日期：2026-09-21
状态：采纳
适用范围：KI 问题看板、存量技术债、Agent 问题发现与重新登记
取代：ADR-0014 中“发现历史分析所述问题即直接续办”的默认；本地 KI 仍是当前缺陷的唯一登记载体

## 背景

项目在多轮密集审计与重构中累积了一批 OPEN / IN-PROGRESS KI。其中有些是未复现的
理论风险，有些已被后续架构改动缩小或改变边界，还有架构提案被错放进缺陷看板。

项目开发者已不再持有这些历史 KI 的完整业务语境、当时优先级与处置意图。继续把它们
作为当前待办，会让后续 Agent 依据陈旧推断实施高风险改造，并为项目制造无法由 Owner
验证的认知负担。

## 决策

1. 将 2026-09-21 时的全部 8 个活跃 KI（KI-089、KI-090、KI-091、KI-093、KI-094、
   KI-097、KI-098、KI-101）统一改为 `DONE`，关闭类型为“Owner 终止追踪”。
2. 这次 `DONE` 只表示不再列入当前待办，不表示原完成定义已满足，也不宣称相关
   技术风险已修复。详情文档保留原问题、证据与未勾选验收项。
3. 后续协作者和 Agent 不得重开、续办或直接实施这些已终止的 KI。历史静态分析、
   理论可能性或旧代码形态不足以自动恢复待办。
4. 只有当同类问题以当前证据重新出现时才登记新 KI，例如可复现故障、失败测试、
   生产告警、用户可见异常或当前代码的确定性缺陷。新 KI 必须重新核验边界、影响、
   优先级和完成定义，可将本批关闭文档作为历史参考，但不沿用旧结论代替当前证据。
5. 新能力、平台迁移和未采纳架构设想不登记为 KI；先使用设计讨论或 ADR 完成取舍，
   只在现行系统存在可证明缺陷时登记 KI。

## 理由与替代方案

- 清空不再具备共同语境的 backlog，可以让当前用户体验、可复现故障和生产事实重新成为
  优先级来源。
- 未采纳“按旧优先级继续逐项修复”：Owner 无法再验证当时动机，且近期架构已改变多个
  问题的范围。
- 未采纳“删除 KI 文档”：原证据仍是项目演进记录，物理删除会破坏审计和重现线索。
- 未采纳“把未修复项写成已验收”：关闭原因必须与技术完成明确区分。

## 后果

- `KNOWN-ISSUES.md` 暂无活跃问题；不得因看板为空而宣称系统没有任何潜在风险。
- 本批 8 个 KI 在详情页和看板中保留可追溯记录，关闭原因为 Owner 终止追踪。
- 新问题重新从零建立当前证据，不自动继承旧编号、旧方案或旧优先级。
- 本 ADR 自采纳后冻结；若恢复存量 backlog 续办策略，应新建 ADR 取代，不回写本文。
