# ADR-0011 本机公共 Harness 与项目适配分离

更新日期：2026-09-11
状态：采纳
适用范围：本机通用 AI 开发工具及 MOD 项目接入

## 背景

全局 Pi 设置曾加载 MOD 专属扩展；项目入口要求重复加载多份长文档。
本机同时有应用、SDK 和小型 Worker 项目，不能共享 MOD 的业务规则或命令目标。

## 决策

公共包负责项目识别、领域索引、有限正文读取、确定性检查和摘要报告；项目声明引用与检查命令。
Pi 复用现有扩展/会话能力，其他 CLI 调用相同脚本。先正式接入 MOD，其他项目保持只读发现。
检查执行由本机项目路径和 manifest 哈希批准；不将该批准描述为 OS 沙箱或脚本安全证明。
旧内容完整保全，入口缩短；不把注释中的旧全文继续送入每次任务上下文。

## 理由与后果

比复制 MOD 的完整规范更适应不同项目；比每次让模型执行固定流程更确定。
减少启动与验收的冗余输入，但不承诺未经测量的 token 节省。
本地公共包需要独立维护；缺席时 MOD 保留原有检查回退。提交门禁仍执行完整检查。
实现与回滚见[本地 Harness 接入](../development/LOCAL-HARNESS.md)。
