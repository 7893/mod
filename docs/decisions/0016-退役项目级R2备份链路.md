# ADR-0016 · 退役项目级 R2 备份链路

- 状态：已采纳
- 日期：2026-09-16
- 关联：[KI-095](../issues/KI-095-项目级R2备份链路退役.md)、[KI-042](../issues/KI-042-灾难恢复能力不足与异机加密备份缺失.md)

## 背景

KI-042 曾建立项目级 R2 备份链路，包括：
- 每日 mysqldump 逻辑导出
- AES-256 加密
- 上传至 Cloudflare R2
- 自动轮转与恢复演练工具

这套方案增加了代码维护面（~500 行脚本 + systemd timer + 测试 + Runbook）。

## 决策

**停用并删除项目级 R2 备份链路**，不再自建异地备份。

## 理由

1. **数据库本身具备备份功能**：MySQL HeatWave 由 Oracle Cloud 托管，平台自带自动备份与时间点恢复（PITR），RPO/RTO 优于自建逻辑导出。

2. **代码已有多重冗余**：
   - 开发机（JPA）本地有完整仓库
   - GitHub 远端托管，自带历史版本
   - 无需额外离线异地备份

3. **维护成本不值得**：自建备份链路需要维护脚本、定时任务、密钥、轮转策略、演练流程，收益与平台原生能力重复。

## 影响

- 删除 `backup_pipeline.py`、`verify_and_restore.py`、`backup_history_to_r2.py` 及相关测试
- 停用 `mod-backup.timer` 和 `mod-backup.service`
- 更新灾备 Runbook，不再声称项目提供 R2 灾备
- R2 存量备份保留至自然过期，密钥暂不销毁

## 替代方案（未采纳）

- 继续维护 R2 备份：冗余，平台已提供
- 迁移到其他备份服务：同样冗余

## 2026-09-17 勘误：平台备份能力边界

“平台自带自动备份与时间点恢复（PITR）”中的 PITR 描述不适用于当前实例。2026-09-17 通过 OCI API
只读核验当前唯一 MySQL.Free DB System：自动增量备份已启用，保留期为 1 天，PITR 为关闭；当日存在
`ACTIVE` 自动备份，较早备份按短保留策略删除。

因此，退役 R2 后的真实边界是：项目接受仅依赖 OCI 短期自动备份的数据库恢复风险，不具备项目级第二副本，
也不具备任意时间点恢复能力。JPA 与 GitHub 的代码副本只能恢复版本化代码和文档，不能恢复数据库业务数据。
本勘误纠正能力依据，不改变“停止维护自研 R2 备份代码”的决策。
