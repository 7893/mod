# ADR-0020 · 新业务采用分阶段审批制证链路

- 状态：ACCEPTED
- 日期：2026-09-21
- 影响范围：业务模拟器、`daily_stats`、实时投影、D 屏运营驾驶舱

## 背景

原快业务剧本在一个周期内同时生成单据、凭证和集成结果，导致当日单据数与凭证数长期机械相等。
数据库虽已具备审批状态和多对多关联表，但运行链路没有真正使用审批等待、驳回、待制证、合并制证
与拆分制证能力。历史数据体量大，重写既无必要，也会破坏其作为项目演进切片的价值。

## 决策

1. 仅对启用后的新记录使用 `正式业务·拟真审批链` 隔离标记；历史记录不回填、不重算、不进入新队列。
2. 新单据依次经过 `审批中 → 已驳回 | 待生成凭证 → 处理完成`。审核是业务阀门，容量受大陆工作日、
   节假日、时段与当期业务量影响，等待时间采用稳定长尾分布，大额单据驳回概率适度提高。
3. 制证独立于提交和审核发生；支持常态 1:1、约两成同单位 N:1 合并以及少量 1:N 拆分，连通分量内
   单据金额与凭证金额严格相等，时间严格保序。
4. `daily_stats` 按各记录真实发生时间分别累计单据、凭证和集成，而非全部归到单据提交日。
5. D7 只展示新链路近 30 日审批/制证事实；D6 收窄但内部 5:7 质量核验结构保持不变。
6. `MOD_APPROVAL_PIPELINE_ENABLED=false` 可立即回退到旧的同周期完整足迹，写库总门禁仍由
   `MOD_SIMULATION_ENGINE_ENABLED` 控制。

## 结果

- 新增单据与凭证不再天然同数，差异由真实状态和跨日积压形成，而非展示层造数。
- 历史数据库零改动，风险边界清晰；新旧口径可通过 `nature` 精确区分。
- D7 的指标是数据库状态派生事实；没有新链路数据时如实显示 0 或 `—`。
- 查询限定近 30 日并保留时间范围条件，避免驾驶舱轮询扫描全部历史单据。
