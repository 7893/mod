# ADR-0019 · 六屏主面板采用连续编号

更新日期：2026-09-21
状态：采纳
适用范围：A–F 六屏主画布的 Zone 编号
取代：ADR-0017 第 4 条中的“旧编号不复用”规则；ADR-0017 其余决策继续有效

## 背景

ADR-0017 允许合并或退役低价值面板，并把 Zone 当作长期稳定坐标。实际完成信息架构去重后，A、C、D 屏
分别留下 A3、C3、D2 等空号。旧坐标虽然保留了变更前的定位，却让当前界面、验收用例和沟通材料需要
额外记忆哪些编号已经退役，用户也无法仅凭编号判断一屏现有多少块主面板。

## 决策

1. 每屏当前主画布的 Zone 必须从 1 开始连续编号，若共有 N 个主面板，编号集合必须严格为
   `{屏名}1 … {屏名}N`，不得存在空号或重复号。
2. 面板合并、退役或插入导致序列变化时，在同一变更中重排受影响编号，并同步源码注释、现行文档、
   自动化测试和视觉验收说明。
3. Zone 只定位当前信息架构，不作为跨版本永久标识；面板业务身份由标题和职责表达。历史文档、旧 ADR、
   已封存证据和 Git 历史继续保留当时编号，不追溯改写。
4. 抽屉、详情页等非主画布区域可以使用 `B6-DETAIL` 一类来源后缀，不计入主面板连续序列。

## 理由与替代方案

- 连续编号让当前界面的数量、顺序和沟通坐标可以直接理解，降低维护者与使用者的认知成本。
- 业务标题承担稳定语义，Zone 承担当前布局定位，避免让展示编号兼任永久数据库主键。
- 未采纳“永久保留退役空号”：它会持续放大历史包袱，并使新面板编号与当前结构脱节。
- 未采纳“删除 Zone”：编号仍是大屏评审、截图验收和问题定位中成本最低的坐标。

## 后果

- 本次重排为：A4–A7 顺延为 A3–A6，C4–C6 顺延为 C3–C5，D3–D7 顺延为 D2–D6；
  B、E、F 已连续，无需改号。
- `data-zone` 属于展示与测试定位契约，不是后端 API；引用旧编号的当前测试和运维说明必须随代码更新。
- 前端测试持续校验每屏主面板编号从 1 连续且不重复，防止后续信息架构调整再次留下空号。
- 本 ADR 自采纳后冻结；若再次改变编号策略，应新增 ADR 取代，不回写本文。
