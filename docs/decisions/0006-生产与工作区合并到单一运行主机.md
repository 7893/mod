# ADR-0006: 生产与工作区合并到单一运行主机

- 状态：采纳（取代 ADR-0005）
- 日期：2026-09-05

## 背景
此前架构区分两处：一处作为源码工作区与开发环境，另一处作为纯部署的生产环境，前端通过
CI 自动 CD 跨主机同步（见 ADR-0005）。项目随后整体迁移，数据库与运行环境统一到单一运行主机。

## 决策
将生产运行与源码工作区合并到**同一台运行主机**：
- 数据库为该主机可达的托管 MySQL（连接信息仅存主机本地环境文件，不入库、不写文档）。
- 后端由该主机的 systemd 服务运行；前端 `dist` 由该主机本地构建、本机 Nginx 直接提供。
- 拟真引擎作为该主机的常驻 systemd 服务运行。
- 不再存在独立的"部署目标主机"，也不再有跨主机的前端自动 CD。

## 理由
- 迁移后旧运行环境已不再承载本项目任何组件，跨主机 CD 失去对象。
- 生产与工作区同机后，构建/重载即影响生产，链路更短、无需把部署密钥托管给第三方 CI。
- 简化运维与文档口径：文档只描述"运行主机"这一角色，不绑定具体主机代号。

## 后果
- 废止并删除跨主机 `deploy.yml` 及其 GitHub Secrets 依赖（旧部署凭据不再使用）。
- CI（Quality gates）保留为纯检查，不做部署。
- 由于生产与工作区同机，**前端构建、服务启停、Nginx 变更一律按生产变更对待，需显式授权**
  （见 `ENFORCEMENT.md`）。
- 现行文档统一采用角色化中性表述（"运行主机 / 生产主机 / 旧运行环境"），不出现具体主机代号；
  迁移前形态的历史文档保留原文并加历史标注，供追溯。
- ADR-0005 标记为已被取代。
