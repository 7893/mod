# ADR-0021 · AI 简报与实时指标按时点分层

- 状态：采纳
- 日期：2026-09-21

## 背景

每日 AI 简报在 HKT 00:30 低频生成，但此前把仍会持续增长的 `docsTodayAdded`、
`vouchersTodayAdded` 作为“今日新增”交给模型。首页实时卡片随后继续接收权威快照与实时投影，导致同一页面中
日报数字与当前数字必然分离，也容易把 00:30 的累计误读为全天终值。

## 决策

1. HKT 00:30 生成的低频 AI 日报以“上一完整自然日”为统计周期；任务从 `daily_stats` 读取该日单据与凭证
   日增，并把该日期写入 `briefing_date`。例如 09-21 00:30 生成 09-20 日报。
2. 日报可同时接收稳定的累计规模、状态、成功率和风险聚合，但不接收尚未封账的日内新增量。模型不得把累计
   规模或上一日计数改写为“今日新增”；原因与行动仍只能表述为待核实。
3. 首页常显日报统计日期，悬停公开 `generatedAt`；后者以后端存储的 UTC 时刻和大盘展示时区格式化。
   读取端只返回不晚于上一完整自然日、且本地生成日期晚于统计日期的记录，以隔离此前按生成日入库的旧口径文本。
4. 今日单据、今日凭证等实时事实仍由 dashboard snapshot 与 live projection 单一链路提供，不让 LLM
   文本承担实时计数职责。

## 后果

- 新生成日报与实时增长数字分属“上一完整日”和“开放中的今日”，不会再形成伪冲突；历史文本不回写。
- 保持每日一次的低调用成本，不用高频调用 LLM 追逐分钟级变化。
- 若上一完整日尚无 `daily_stats`，任务如实降级且不写假日报；不得退回开放中的当日累计。
