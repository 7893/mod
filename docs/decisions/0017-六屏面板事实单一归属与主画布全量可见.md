# ADR-0017: 六屏面板采用事实单一归属与主画布全量可见

- 状态：采纳
- 日期：2026-09-21

## 背景

ADR-0007 已将驾驶舱收敛为六屏叙事，但早期实现继续把 Zone 数量和既有 Grid 当作不可变目标，导致同一事实
在总览与专业屏重复展示，也出现用页签或条件分支整页替换主面板的情况。面板数量得到维持，但决策职责、
信息密度和可发现性反而下降。

## 决策

六屏路由与领域职责保持不变，屏内结构遵循以下规则：

1. 同一业务事实只设一个专业面板作为完整事实页；A 屏等总览只保留摘要、状态和下钻入口。
2. 设计画布内所有主面板默认同时可见，不用页签或 `v-if` 整页替换另一组主面板。
3. 台账明细通过有限行数、分页、宽抽屉或面板内局部滚动承载，标题、主 KPI 和主图不依赖滚动出现。
4. Zone 是稳定的沟通坐标，不是必须凑满的数量指标；没有独立决策价值的 Zone 可以合并或退役，旧编号不复用表达新事实。
5. 缺失事实显示明确空态或“未核验”，不得用 0、冻结基线或装饰图表填充空间。

## 理由

- 单一事实归属减少跨屏口径漂移，也让专业屏承担完整解释责任。
- 主画布全量可见让观众无需猜测页签内还有哪些内容，适合常驻大屏和巡检场景。
- 把 Zone 视为坐标而非配额，可以删除重复内容，同时保留讨论和测试中的稳定定位。
- 选择抽屉、分页和局部滚动承载明细，比压缩全部内容或构造高参数万能组件更可维护。

未采纳“维持历史 36 个 Zone 不增删”的方案，因为它会迫使低价值或重复面板长期占位；也未采纳“六屏完全同构”，
因为各业务域的决策问题和信息密度不同。

## 后果

- `FRONTEND-ARCHITECTURE-AND-CONSTRAINTS.md` 维护现行六屏职责、骨架、物料和 Token 契约；KI-102 记录本轮实施与验收进度。
- 面板合并、退役或事实迁移必须同步现行文档、相关测试和视觉验收场景。
- 自动化几何检查不能替代人工审美与信息层级确认；重大布局变化在人工确认前不得更新截图基线。
- 本决策细化 ADR-0007 的屏内信息架构，不取代其六屏叙事结论，也不要求抽象出万能图表组件。
