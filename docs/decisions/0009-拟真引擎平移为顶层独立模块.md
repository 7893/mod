# ADR-0009: 拟真引擎平移为顶层独立模块

- 状态：采纳
- 日期：2026-09-06

## 背景
拟真引擎（`backend/app/simulation/`）在运行层面已经是独立的 systemd 服务（`mod-simulator`），
与后端 API（`mod-api`）独立进程、独立运行、互不依赖。但代码物理上仍作为"后端的子模块"存放，
不能体现引擎作为一等公民的定位。

## 决策
将 `backend/app/simulation/` 平移到项目顶层，成为与 `backend/`、`frontend/` 并列的独立目录
`simulation/`，共用同一个 Python 环境（`.venv`），保持在同一仓库内：

```
mod/
├── backend/       ← 只读 API（mod-api）
├── frontend/      ← 驾驶舱大屏
├── simulation/    ← 拟真引擎（mod-simulator）← 从 backend/app/ 平移
└── ...
```

## 理由
- 物理结构上体现引擎独立性，不是后端的附属子模块
- 运行层面已独立（systemd 服务），代码结构补上对应
- 不新建独立 repo（单人主控 + agy，无跨团队协作需求，代价大于收益）
- 共用 `.venv` 简化依赖管理

## 后果
- `simulation/` 成为顶层 Python 包，import 路径从 `from app.simulation.*` 改为 `from simulation.*`
- `backend/tests/` 中的测试迁移到 `simulation/tests/`（或保留在 backend/tests/ 并调整 sys.path）
- `scripts/agy/run_simulator_service.py` 启动脚本调整 sys.path 指向顶层
- `mod-simulator.service` WorkingDirectory 改为 `/home/ubuntu/mod`（已是如此，不变）
- `backend/app/business_simulator.py` 的旧 simulation import 一并清理（旧模拟器残留）
- 见 `docs/issues/KI-032-拟真引擎平移顶层.md`
