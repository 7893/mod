# ADR-0007: 驾驶舱收敛为六屏叙事，对齐观众三大关注

- 状态：采纳
- 日期：2026-09-05

## 背景
前端历史上有 7 个候选屏（项目总览、建设进度、上线推广、数据准备台账 `/data`、业务运营、问题清单、
智能研判），但顶栏是"左3 + 中央标题 + 右3"的对称大屏布局，只容纳 6 个入口——`/data` 有路由和内容却
从未进入导航（自初始提交即漏加），等于隐藏页。同时按 `BUSINESS-SIMULATION-ENGINE.md` 第十三章定位，
核心观众（懂业务的高层）看系统只回答三个问题：**整体推进到哪、哪个单位有风险、钱花得合不合规**。
现状 7 屏中有 4 屏都在讲"进度"（总览/建设/上线/数据准备），而"风险"与"合规"各只有半个屏承载，
叙事失衡：进度过重，风险与合规不突出。

## 决策
将驾驶舱收敛为 **6 屏叙事**，屏的取舍与顺序对齐观众三大关注 + 次线佐证，并保持顶栏左右对称：

| 序号 | 屏 | 讲什么 | 观众问题 |
|---|---|---|---|
| A | 项目总览 | 全局进度 + 四级下钻入口 | 进度（总） |
| B | 建设进度 | 各单位建设 + 数据准备台账（并入 `/data`） | 进度 |
| C | 上线推广 | 批次 / 双轨 / 上线率 | 进度 |
| D | 风险预警 | 哪个单位要掉队（AI 预测 + 困难户） | 风险 |
| E | 合规监督 | 钱花得合不合规（单位级概览） | 合规 |
| F | 业务运营 | 上线后业务在跑（次线佐证，收尾） | 佐证 |

导航布局：左 3（A/B/C）+ 中央标题 + 右 3（D/E/F）。URL 采用序号路径（`/a`~`/f`），
展示用中文名（观众看中文，URL 用序号无妨）。

## 理由
- 直接对齐观众三大问题（进度/风险/合规），主线突出、次线收尾，符合"建设管控真 > 业务数据真"。
- 消除"进度屏过多、风险合规不突出"的失衡：把 4 个进度屏收敛为 3 个（数据准备并入建设），
  腾出的位置让"风险预警"与"合规监督"各成独立一屏。
- 保持大屏对称美观（左3右3），符合面向高层的展示气质。
- 替代方案：①保留 7 屏做左4右3——破坏对称，否决；②凑第 8 屏配平——为对称造页面不健康，否决；
  ③删掉 `/data`——其台账内容有价值，选择并入而非删除。

## 后果
- 轻量改动（主控执行）：导航收敛为 6 屏、屏命名与定位调整（"问题清单"→"合规监督"、
  "智能研判"→"风险预警"）、URL 改序号路径、路由收敛。`/data` 路由暂留、内容合并留后续。
- 重量改动（写 KI 派 agy，主控验收）：DataView 台账内容并入 ConstructionView；IssuesView 转"合规监督"
  视角；InsightsView 转"风险预警"重心。见 KI-029。
- 遵守单一正统命名（AGENTS.md）：新命名不带版本后缀；旧命名不保留并存变体。
- 内容并入采用"搬不删、保留可追溯"；涉及前端结构变更，分步执行 + 每步 make check + 可回退。
