# ADR-0004: 停用与废弃内容一律归档，不删除

- 状态：已部分取代（2026-09-17）
- 日期：2026-09-04

## 背景
项目中不断产生停用/废弃的资产：历史脚本、停用的协作状态机、历史过程文档等。
需要一致的处置方式，避免误删可追溯资产，也避免它们冒充现行内容。

## 决策
停用/废弃内容**移入 `archive/`（回收站）或 `docs/history/`**，保留内容不改，
不物理删除。仅从活跃代码路径与扫描范围中移出。

## 理由
- 归档保留可追溯性；删除不可逆。
- 项目本身为实验/演示性质，历史资产有参考与考证价值。
- 与 ADR-0001（订正优先非删除）一脉相承：默认可逆、慎用不可逆。

## 后果
- 含明文凭据的废弃脚本已归档 `archive/legacy-db-scripts/`；协作状态机归档
  `archive/legacy-collaboration/`；历史编号文档归档 `docs/history/`。
- 归档区排除出 pre-commit 凭据扫描（回收站不作活跃代码扫描）。
- 彻底删除（如 Git 历史清理）属高风险，需另行显式授权。

## 后续修订

2026-09-17 经用户逐批明确确认，物理删除已退出运行链路的
`archive/legacy-db-scripts/` 与 `archive/v2-generation-fixes/`。前者包含失效的历史明文凭据，
继续保留没有运行或审计收益。同日经后续逐批确认，删除旧界面与临时研究目录
`archive/workbench/`、`archive/legacy-frontend/`。
随后同样经单独确认，删除未采用的 `archive/legacy-cloudflare-worker/` 与
`archive/legacy-components/` 配置文件；未操作对应外部资源。
同日，经单独确认删除已停用的自研协作状态机目录 `archive/legacy-collaboration/`。
最后经统一确认，删除旧 harness 与临时脚本和重复部署配置目录。废弃 issue 模板因受 Git 跟踪，
按文档治理门禁继续保留。
同日删除其余未跟踪归档，包括旧 USA 部署快照、一次性业务脚本、V1 工具备份与旧 Git 历史备份；
`archive/` 最终只保留说明文件和受 Git 跟踪的历史 issue 模板。
今后如新增归档内容，删除前仍需单独确认。
